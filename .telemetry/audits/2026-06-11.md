## Identity Management

| Call Type | Present | Location | Details |
|-----------|---------|----------|---------|
| identify() | Partial | `static/index.html` | Anonymous UUID generated in `localStorage.learner_id` on first visit. No traits set. |
| group() | NO | — | No group hierarchy exists |
| page()/screen() | NO | — | Hash-based routing with no page view tracking |
| reset()/logout | NO | — | No logout flow; anonymous identity persists until localStorage cleared |

**Identity flow:** On first page load, if `localStorage.learner_id` is empty, a UUID is generated via `crypto.randomUUID()` or fallback. This ID is sent as the `X-Learner-ID` HTTP header on all API requests. No registration or login exists — all users are anonymous.

## Observed Patterns

- **Naming style:** mixed — localStorage keys use `snake_case`, API paths use `/slash/separated`
- **Naming format:** mixed — no formal event naming convention. localStorage keys are descriptive nouns (`dojo_progress`), API endpoints are `object/verb` (`dojo/submit`)
- **Centralization:** Scattered — tracking calls are inline throughout `static/index.html` (single 6500+ line file) and individual FastAPI endpoint handlers in `backend/server.py`. No centralized tracking module, wrapper function, or middleware.
- **Error handling:** Server-side uses try/catch with `logger.error()`. Client-side localStorage calls have no error handling.
- **Blocking calls:** Server-side tracking is synchronous within request handlers (not fire-and-forget).

## Hygiene Notes

*Factual observations, not recommendations.*

1. **Dual storage with no sync:** Client-side `dojo_progress` localStorage and server-side `POST /api/dojo/submit` both record exercise results independently. If one fails, data diverges silently.
2. **No cross-device persistence:** Client-side localStorage data (notes, progress, submissions, UI state) is lost if the user switches browsers or clears storage. There is no mechanism to restore client-side data from the server.
3. **Anonymous-only identity:** No registration or login flow exists. The `learner_id` UUID has no attached traits (email, name, etc.). No way to merge identities across devices.
4. **No external analytics platform:** No Segment, Amplitude, Mixpanel, PostHog, GA, or any third-party analytics SDK is present in the codebase.
5. **Monolithic frontend:** All client-side tracking calls live in a single `static/index.html` file (6500+ lines). Tracking logic is interleaved with UI rendering logic.
6. **No event timestamps on client side:** Client-side localStorage updates (except `dojo_submissions`) do not record when events occurred, only the latest state.
7. **Counter without context:** `estimates_calculated_count` is a simple integer counter with no breakdown by architecture, paper, or time period.
8. **No navigation or feature adoption tracking:** No events capture which pages/features users visit, feature discovery, or onboarding funnel progression.
9. **No lifecycle events:** No signup, activation, return, or churn signals are tracked.
