# Faster R-CNN

## 1. Overview
Faster R-CNN, introduced in 2015 by Shaoqing Ren, Kaiming He, Ross Girshick, and Jian Sun (Microsoft Research), is one of the most influential architectures in computer vision history. It established the definitive two-stage deep object detection paradigm. Faster R-CNN eliminated the final remaining computational bottleneck of two-stage detectors—CPU-based region proposal generation (Selective Search)—by introducing a **Region Proposal Network (RPN)**. The RPN is a fully convolutional network that shares the backbone's feature map with the detection head, generating high-quality region proposals directly on the GPU in just 10ms. By introducing **Anchor Boxes** (multi-scale, multi-aspect reference frames evaluated at every spatial location), Faster R-CNN unified proposal generation and object classification into a single, fully trainable neural network operating at real-time speeds (5–17 FPS).

:::note
Faster R-CNN's key insight: "The convolutional feature map used by the detector for classification can also be used to generate region proposals for free via a lightweight Region Proposal Network (RPN)."
:::

## 2. Historical Context
### The R-CNN → Fast R-CNN → Faster R-CNN Story: Eliminating Bottlenecks (Part 3)
The saga of two-stage object detection reaches its natural completion with Faster R-CNN.

1. **R-CNN (2013):** Proved deep learning works for object detection, but had a massive **CNN Computation Bottleneck**—running AlexNet 2,000 times per image (47s/image).
2. **Fast R-CNN (2015):** Eliminated the CNN computation bottleneck by sharing a single feature map across all proposals via RoI Pooling. This sped up GPU execution from 47 seconds to 0.3 seconds. However, Fast R-CNN suffered from a glaring **CPU Proposal Bottleneck**: it still relied on Selective Search, an offline CPU algorithm taking **2.0 seconds per image** to compute proposals.
3. **Faster R-CNN (2015):** Eliminated the CPU proposal bottleneck completely. Ren et al. asked: *Why use an external CPU algorithm when the GPU feature map already contains rich semantic features?* They designed the **Region Proposal Network (RPN)**—a small 3x3 convolutional head sliding over the GPU feature map. The RPN evaluates 9 **Anchor Boxes** (3 scales $\times$ 3 aspect ratios) at every grid cell, outputting objectness scores and bounding box deltas.

By replacing Selective Search with the RPN, proposal generation time dropped from **2,000ms to 10ms**, enabling true end-to-end GPU object detection at 17 FPS.

## 3. Problem It Solves
Faster R-CNN solves three critical engineering problems:
1. **CPU Region Proposal Latency:** Replaces CPU Selective Search (~2,000ms per image) with GPU-native RPN (~10ms per image).
2. **Fixed Anchorless Proposal Generation:** Introduces **Anchor Boxes**—a fixed multi-scale, multi-aspect reference frame grid that avoids multi-scale image pyramids or sliding window scale resampling.
3. **Disjoint Network Optimization:** Provides a 4-Step Alternating Training strategy (later simplified to end-to-end joint training) that allows the RPN and Fast R-CNN detection heads to share a single convolutional backbone without degrading performance.

## 5. Layer-by-Layer Breakdown
Faster R-CNN consists of two module networks sharing a single backbone:

**1. Shared Backbone (VGG-16 or ResNet-50):**
- Takes an input image $(3 \times H \times W)$ and extracts a feature map $X \in \mathbb{R}^{C \times H/16 \times W/16}$ (e.g., $C=512$ for VGG-16, $C=1024$ for ResNet-50 C4).

**2. Region Proposal Network (RPN):**
- **Slide Conv:** A $3 \times 3$ convolution with 512 filters (padding 1) and ReLU, sliding across the $H/16 \times W/16$ feature map.
- **Classification Branch (`rpn_cls_score`):** A $1 \times 1$ convolution outputting $2k$ scores per spatial location (where $k=9$ anchors). Represents foreground vs. background objectness logits.
- **Regression Branch (`rpn_bbox_pred`):** A $1 \times 1$ convolution outputting $4k$ bounding box regression deltas $(\Delta x, \Delta y, \Delta w, \Delta h)$ per spatial location.

**3. Proposal Layer & Non-Maximum Suppression (NMS):**
- At each spatial location $(h, w)$, applies predicted deltas to the 9 anchor boxes.
- Filters out-of-bounds anchors, sorts by objectness score, keeps top 12,000 proposals, applies NMS with IoU threshold 0.7, and outputs top $N_{\text{roi}} = 300$ (or 2,000 during training) proposals.

**4. RoI Pooling / RoIAlign:**
- Projects the $N_{\text{roi}}$ proposals onto the shared feature map and pools them to fixed $7 \times 7 \times C$ tensors.

**5. Fast R-CNN Detection Head:**
- Passes $7 \times 7 \times C$ features through shared FC layers (or ResNet Stage 5) to output final class probabilities ($K+1$ classes) and final refined bounding box deltas $(K+1) \times 4$.

## 6. Tensor Flow Walkthrough
Let's trace tensors through Faster R-CNN (VGG-16 backbone) for 1 image $(600 \times 800)$, $K=20$ classes, $k=9$ anchors per grid cell.

1. **Backbone Output:**
   - Input Image: `(1, 3, 600, 800)`
   - Feature Map: `(1, 512, 38, 50)`  (Spatial grid $38 \times 50 = 1,900$ locations)
2. **RPN Execution:**
   - 3x3 Conv: `(1, 512, 38, 50)`
   - `rpn_cls_score` ($1\times1$ Conv to $2k = 18$): `(1, 18, 38, 50)` $\rightarrow$ Reshape: `(1, 1900 * 9, 2)` (17,100 anchors total)
   - `rpn_bbox_pred` ($1\times1$ Conv to $4k = 36$): `(1, 36, 38, 50)` $\rightarrow$ Reshape: `(1, 17100, 4)`
3. **Anchor Box Decoding & NMS:**
   - Apply 17,100 deltas to 17,100 pre-defined Anchor Boxes $\rightarrow$ `(17100, 4)`.
   - Apply GPU NMS $\rightarrow$ Output top $N_{\text{roi}} = 300$ RoI boxes `(300, 4)`.
4. **RoI Pooling Execution:**
   - Input: Feature Map `(1, 512, 38, 50)` and RoIs `(300, 5)` (with batch index 0).
   - RoI Pool Output: `(300, 512, 7, 7)`
5. **Detection Head Execution:**
   - Flatten $\rightarrow$ FC6 $\rightarrow$ FC7: `(300, 4096)`
   - `cls_score`: Linear(4096 $\rightarrow 21$) $\rightarrow$ `(300, 21)` Logits
   - `bbox_pred`: Linear(4096 $\rightarrow 84$) $\rightarrow$ `(300, 84)` Deltas

## 7. Mathematical Foundations

### RPN Anchor Box Design (9 Anchors per Spatial Location)
An **Anchor Box** is a fixed-size reference bounding box centered at each spatial grid location $(h, w)$ of the feature map. 

At each of the $W' \times H'$ spatial locations (e.g., $38 \times 50 = 1,900$ locations), RPN constructs $k = 9$ anchor boxes defined by **3 Scales** and **3 Aspect Ratios**:

- **3 Scales (Box Areas):** $128^2, 256^2, 512^2$ pixels.
- **3 Aspect Ratios (Width : Height):** $1:1, 1:2, 2:1$.

Combining 3 scales $\times$ 3 ratios yields $k = 9$ anchor boxes per cell:

| Anchor Index | Scale (Area) | Aspect Ratio ($W:H$) | Anchor Width ($W_a$) | Anchor Height ($H_a$) |
|---|---|---|---|---|
| 1 | $128^2$ | 1:1 | 128 | 128 |
| 2 | $128^2$ | 1:2 | 90 | 181 |
| 3 | $128^2$ | 2:1 | 181 | 90 |
| 4 | $256^2$ | 1:1 | 256 | 256 |
| 5 | $256^2$ | 1:2 | 181 | 362 |
| 6 | $256^2$ | 2:1 | 362 | 181 |
| 7 | $512^2$ | 1:1 | 512 | 512 |
| 8 | $512^2$ | 1:2 | 362 | 724 |
| 9 | $512^2$ | 2:1 | 724 | 362 |

For a feature map of size $W' \times H'$, the total number of anchor boxes in the image is:
$$N_{\text{anchors}} = W' \times H' \times k = 38 \times 50 \times 9 = 17,100 \text{ anchors}$$

### RPN Multi-Task Loss Formulation
RPN minimizes a joint loss over sampled anchor mini-batches ($N_{\text{cls}} = 256$):

$$\mathcal{L}_{\text{RPN}}\left(\{p_i\}, \{t_i\}\right) = \frac{1}{N_{\text{cls}}} \sum_i \mathcal{L}_{\text{cls}}\left(p_i, p_i^*\right) + \lambda \frac{1}{N_{\text{reg}}} \sum_i p_i^* \mathcal{L}_{\text{reg}}\left(t_i, t_i^*\right)$$

where:
- $p_i$ is the predicted objectness probability of anchor $i$.
- $p_i^*$ is ground-truth label: $1$ if anchor $i$ is positive ($\text{IoU} \ge 0.7$ with any ground-truth box), $0$ if negative ($\text{IoU} < 0.3$).
- $t_i = (t_x, t_y, t_w, t_h)$ is predicted 4-coordinate bounding box delta.
- $t_i^*$ is ground-truth box delta target relative to anchor box $A_i = (x_a, y_a, w_a, h_a)$:
  $$t_x^* = \frac{x^* - x_a}{w_a}, \quad t_y^* = \frac{y^* - y_a}{h_a}, \quad t_w^* = \log\left(\frac{w^*}{w_a}\right), \quad t_h^* = \log\left(\frac{h^*}{h_a}\right)$$
- $\mathcal{L}_{\text{reg}}$ is Smooth $L_1$ loss.

## 8. Training Procedure
- **Anchor Sampling for RPN:** 256 anchors per image (128 positive, 128 negative). An anchor is positive if IoU $\ge 0.7$ with a ground-truth box; negative if IoU $< 0.3$.
- **4-Step Alternating Training:**
  1. Train RPN from ImageNet weights.
  2. Train Fast R-CNN detection head using proposals from Step 1 RPN.
  3. Re-initialize RPN with Step 2 backbone weights, freeze backbone, fine-tune RPN layers.
  4. Keeping backbone frozen, fine-tune Fast R-CNN detection head.
- *(Modern implementation uses 1-stage joint end-to-end training where RPN and detection losses are summed directly).*

## 9. PyTorch Implementation
Here is a complete PyTorch implementation of the **Region Proposal Network (RPN)** with 9 anchor box projections and shape assertions.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class RegionProposalNetwork(nn.Module):
    def __init__(self, in_channels=512, mid_channels=512, num_anchors=9):
        super().__init__()
        self.num_anchors = num_anchors
        
        # 3x3 Conv slide over feature map
        self.conv1 = nn.Conv2d(in_channels, mid_channels, kernel_size=3, padding=1)
        
        # 1x1 Conv for Objectness Score (2 scores per anchor: bg vs fg)
        self.cls_head = nn.Conv2d(mid_channels, num_anchors * 2, kernel_size=1)
        
        # 1x1 Conv for Box Deltas (4 deltas per anchor: dx, dy, dw, dh)
        self.reg_head = nn.Conv2d(mid_channels, num_anchors * 4, kernel_size=1)

    def forward(self, x):
        # x shape: (B, in_channels, H_feat, W_feat)
        B, C, H_feat, W_feat = x.shape
        
        # Slide 3x3 conv
        t = F.relu(self.conv1(x)) # (B, 512, H_feat, W_feat)
        
        # Predict Objectness Logits
        rpn_cls_logits = self.cls_head(t) # (B, 18, H_feat, W_feat)
        # Reshape to (B, H_feat * W_feat * num_anchors, 2)
        rpn_cls_logits = rpn_cls_logits.permute(0, 2, 3, 1).contiguous()
        rpn_cls_logits = rpn_cls_logits.view(B, H_feat * W_feat * self.num_anchors, 2)
        
        # Predict Bounding Box Regression Deltas
        rpn_bbox_deltas = self.reg_head(t) # (B, 36, H_feat, W_feat)
        # Reshape to (B, H_feat * W_feat * num_anchors, 4)
        rpn_bbox_deltas = rpn_bbox_deltas.permute(0, 2, 3, 1).contiguous()
        rpn_bbox_deltas = rpn_bbox_deltas.view(B, H_feat * W_feat * self.num_anchors, 4)
        
        return rpn_cls_logits, rpn_bbox_deltas

if __name__ == "__main__":
    B = 2
    in_channels = 512
    H_feat, W_feat = 38, 50 # Feature map size for 600x800 input
    num_anchors = 9
    
    rpn = RegionProposalNetwork(in_channels=in_channels, mid_channels=512, num_anchors=num_anchors)
    
    # Dummy Feature Map (B, 512, 38, 50)
    dummy_feat = torch.randn(B, in_channels, H_feat, W_feat)
    
    cls_logits, bbox_deltas = rpn(dummy_feat)
    
    total_anchors = H_feat * W_feat * num_anchors # 38 * 50 * 9 = 17,100
    
    print(f"Feature Map Shape:      {dummy_feat.shape}")
    print(f"RPN Cls Logits Shape:   {cls_logits.shape}")
    print(f"RPN BBox Deltas Shape:  {bbox_deltas.shape}")
    print(f"Total Anchors per Img:  {total_anchors}")
    
    assert cls_logits.shape == (B, total_anchors, 2), f"Expected ({B}, {total_anchors}, 2), got {cls_logits.shape}"
    assert bbox_deltas.shape == (B, total_anchors, 4), f"Expected ({B}, {total_anchors}, 4), got {bbox_deltas.shape}"
    print("RPN Architecture verification successful!")
```

## 10. Strengths
- **GPU-Native Proposal Generation:** RPN generates region proposals in ~10ms on GPU, eliminating CPU Selective Search.
- **Unified End-to-End Network:** Single neural network handles feature extraction, proposal generation, classification, and regression.
- **Translation Invariance:** Anchor box design ensures translation invariance across image coordinates.
- **High Accuracy Benchmark:** Set historical records (73.2% mAP on VOC 2007) and established the two-stage golden standard.

## 11. Weaknesses
- **Two-Stage Latency (10–17 FPS):** While fast, two-stage evaluation (RPN + RoI Pooling + Head) is slower than single-stage detectors like YOLO or SSD.
- **RoI Pooling Quantization:** Uses integer quantization ($\lfloor x/16 \rfloor$), causing minor spatial misalignment (fixed later by RoIAlign in Mask R-CNN).

## 12. Research Evolution
Faster R-CNN completed the classic R-CNN trilogy. It served as the foundation for **FPN** (Feature Pyramid Networks, 2016), **Mask R-CNN** (2017), and **Cascade R-CNN** (2018).

## 13. Interview Questions

**Q1: Explain how RPN anchor boxes handle objects of different scales and aspect ratios without resizing the image.**
**A1:** Instead of multi-scale image pyramids, RPN evaluates 9 fixed reference anchor boxes (3 scales: $128^2, 256^2, 512^2 \times$ 3 aspect ratios: 1:1, 1:2, 2:1) at every spatial location of the feature map. The $1\times1$ convolution outputs predictions relative to these pre-defined anchor geometry reference frames.

**Q2: How many total anchor boxes are evaluated for a $600 \times 800$ image with a VGG-16 backbone (stride 16)?**
**A2:** Stride 16 reduces spatial size to $38 \times 50 = 1,900$ grid cells. With $k=9$ anchors per grid cell, the total number of evaluated anchor boxes is $38 \times 50 \times 9 = 17,100$ anchors.

**Q3: What are the IoU criteria for labeling an anchor as positive vs. negative during RPN training?**
**A3:** 
- **Positive:** An anchor is positive if (1) it has the highest IoU overlap with a ground-truth box, OR (2) its IoU overlap is $\ge 0.7$ with any ground-truth box.
- **Negative:** An anchor is negative if its IoU overlap is $< 0.3$ with all ground-truth boxes.
- Anchors with $0.3 \le \text{IoU} < 0.7$ are ignored during loss computation.

**Q4: What is the purpose of Non-Maximum Suppression (NMS) in the RPN output?**
**A4:** Because adjacent feature grid cells predict highly overlapping proposals for the same object, RPN generates many duplicate candidate boxes. NMS sorts proposals by objectness score and suppresses redundant boxes that have an IoU $\ge 0.7$ with higher-scoring proposals, reducing proposal count from 17,100 to ~2,000 during training (or 300 during inference).

**Q5: Compare the inference speeds of R-CNN, Fast R-CNN, and Faster R-CNN.**
**A5:**
- **R-CNN:** ~47 seconds per image (Selective Search CPU + 2,000 AlexNet passes).
- **Fast R-CNN:** ~2.3 seconds per image (1 CNN pass on GPU, but 2.0s stuck on CPU Selective Search).
- **Faster R-CNN:** ~0.2 seconds / 17 FPS (1 CNN pass + GPU RPN proposal generation in 10ms).
