# DETR

## 1. Overview
DETR (Detection Transformer), introduced in 2020 by Nicolas Carion, Francisco Massa, Gabriel Synnaeve, Nicolas Usunier, Alexander Kirillov, and Sergey Zagoruyko (FAIR), established the modern **End-to-End Object Detection with Transformers** paradigm. Before DETR, object detectors relied heavily on complex hand-crafted components—such as anchor box generation, region proposal networks (RPN), spatial grid assignments, and Non-Maximum Suppression (NMS) post-processing. DETR completely eliminated all hand-crafted components, reformulating object detection as a direct **Set Prediction Problem**. By combining a standard CNN backbone with a Transformer encoder-decoder and a bipartite matching loss (**Hungarian Loss**), DETR predicts a fixed set of $N=100$ object queries directly, outputting unique bounding boxes and class labels in a single forward pass without NMS.

:::note
DETR's fundamental breakthrough: "Object detection can be solved end-to-end as a set prediction task using a Transformer encoder-decoder paired with Hungarian bipartite matching loss, eliminating anchor boxes, spatial priors, and NMS."
:::

## 2. Historical Context
For over two decades, object detection was built around hand-engineered spatial priors:
- **Anchor Boxes & Grids:** Faster R-CNN, YOLO, and SSD defined thousands of overlapping anchor boxes per image, relying on hand-tuned IoU matching thresholds to assign targets.
- **Non-Maximum Suppression (NMS):** Because dense detectors output duplicate overlapping boxes for a single object, NMS post-processing was required to filter duplicates using arbitrary IoU thresholds.

In 2020, FAIR researchers realized that the self-attention mechanism of Transformers naturally models global relationships between all image tokens and object queries. If paired with a loss function that enforces unique 1-to-1 matching between predictions and ground-truth objects, the Transformer could learn to output exactly ONE box per real object. This birthed DETR, ushering in the era of DETR-based architectures in computer vision.

## 3. Problem It Solves
### Why Removing Anchors Simplifies the Object Detection Pipeline
Traditional object detectors were constrained by hyperparameter-heavy anchor box engineering:
1. **Eliminating Anchor Box Hyperparameters:** Anchor-based models require manual tuning of anchor scales, aspect ratios, spatial strides, and IoU matching thresholds (e.g., positive if IoU $> 0.7$, negative if IoU $< 0.3$). Removing anchors eliminates these hyperparameter tuning dependencies completely; DETR predicts continuous box coordinates normalized to $[0, 1]^4$ directly.
2. **Eliminating Non-Maximum Suppression (NMS):** Classical detectors output thousands of duplicate boxes for one physical object, requiring non-differentiable NMS post-processing to clean up predictions. NMS parameters (e.g., IoU threshold = 0.5) can cause failures in dense crowds. DETR uses a **Bipartite Matching Loss** during training that enforces a strict 1-to-1 matching between queries and ground-truth objects, forcing the model to natively output non-overlapping, unique predictions and eliminating NMS.
3. **Removing Complex Spatial Assigners:** Direct set prediction simplifies the code pipeline from thousands of lines of C++/CUDA anchor assigner code to clean, standard PyTorch matrix operations.

## 5. Layer-by-Layer Breakdown
DETR simplifies the object detection pipeline into three main modules:

**1. CNN Backbone & 1x1 Projection:**
- ResNet-50 / ResNet-101 extracts a $2048 \times H/32 \times W/32$ feature map.
- A $1 \times 1$ convolution reduces channels from 2048 to $d=256$.
- Spatial dimensions are flattened into a 1D sequence of length $S = (H/32) \times (W/32)$.

**2. Transformer Encoder (6 Layers):**
- Processes the sequence of $S$ image tokens ($256$-d).
- Fixed 2D sine/cosine positional encodings are added to queries and keys at every self-attention layer to preserve spatial layout.
- Computes global self-attention across all image pixels, modeling global context.

**3. Transformer Decoder (6 Layers):**
- Takes $N=100$ learned, trainable **Object Queries** $Q \in \mathbb{R}^{N \times 256}$ (initialized as zero vectors with learned positional embeddings).
- **Self-Attention:** Object queries interact with each other to ensure unique predictions.
- **Cross-Attention:** Object queries attend to the encoder's output image memories.
- Positional encodings are added to query and key vectors in every attention block.

**4. Prediction Heads (FFNs):**
- **Class Head:** A 1-layer Linear projection mapping each query to $K+1$ class logits ($K$ categories + 1 "No-Object" background class $\emptyset$).
- **Box Head:** A 3-layer MLP with ReLU activations predicting normalized center coordinates, width, and height $(\hat{x}_c, \hat{y}_c, \hat{w}, \hat{h}) \in [0, 1]^4$.

## 6. Tensor Flow Walkthrough
Let's trace tensors through DETR for input `(B, 3, 800, 1066)`, $N=100$ object queries, $d=256$, $K=90$ COCO classes.

1. **Backbone Output:**
   - Input Image: `(B, 3, 800, 1066)`
   - ResNet-50 $C_5$: `(B, 2048, 25, 34)`  ($800/32 = 25, 1066/32 = 33.3 \rightarrow 34$)
2. **Feature Projection & Flattening:**
   - 1x1 Conv: `(B, 256, 25, 34)`
   - Flatten spatial dims $S = 25 \times 34 = 850$ tokens $\rightarrow$ `(850, B, 256)`
3. **Transformer Encoder Execution:**
   - Adds 2D Fixed Positional Encodings `(850, B, 256)`.
   - Passes through 6 Encoder layers $\rightarrow$ Output Memory: `(850, B, 256)`.
4. **Transformer Decoder Execution:**
   - Input: $N=100$ Object Queries `(100, B, 256)`.
   - Passes through 6 Decoder layers with cross-attention over Memory `(850, B, 256)`.
   - Output Query Embeddings: `(100, B, 256)` $\rightarrow$ Permute to `(B, 100, 256)`.
5. **Prediction Heads Output:**
   - **Class Logits:** Linear(256 $\rightarrow 91$) $\rightarrow$ `(B, 100, 91)`
   - **Box Coordinates:** 3-Layer MLP(256 $\rightarrow 256 \rightarrow 256 \rightarrow 4$) + Sigmoid $\rightarrow$ `(B, 100, 4)`

## 7. Mathematical Foundations

### 1. Hungarian Bipartite Matching Cost
Let $y = (c_i, b_i)$ be the set of ground-truth objects, padded with no-object elements $\emptyset$ to size $N=100$.
Let $\hat{y} = \{ (\hat{p}_i, \hat{b}_i) \}_{i=1}^N$ be the set of $N$ predictions.

We search for a 1-to-1 permutation $\hat{\sigma} \in \mathfrak{S}_N$ of predictions that minimizes the matching cost:

$$\hat{\sigma} = \arg\min_{\sigma \in \mathfrak{S}_N} \sum_{i=1}^N \mathcal{L}_{\text{match}}(y_i, \hat{y}_{\sigma(i)})$$

For a ground-truth target $y_i = (c_i, b_i)$:
$$\mathcal{L}_{\text{match}}(y_i, \hat{y}_{\sigma(i)}) = -\mathbf{1}_{\{c_i \neq \emptyset\}} \hat{p}_{\sigma(i)}(c_i) + \mathbf{1}_{\{c_i \neq \emptyset\}} \mathcal{L}_{\text{box}}(b_i, \hat{b}_{\sigma(i)})$$

The optimal permutation $\hat{\sigma}$ is computed efficiently using the **Hungarian Algorithm** (`scipy.optimize.linear_sum_assignment`).

### 2. Hungarian Loss Function
Once optimal pairs $\hat{\sigma}$ are assigned, the Hungarian Loss computes negative log-likelihood for classification and a combination of $L_1$ and GIoU loss for boxes:

$$\mathcal{L}_{\text{Hungarian}}(y, \hat{y}) = \sum_{i=1}^N \left[ -\log \hat{p}_{\hat{\sigma}(i)}(c_i) + \mathbf{1}_{\{c_i \neq \emptyset\}} \mathcal{L}_{\text{box}}(b_i, \hat{b}_{\hat{\sigma}(i)}) \right]$$

$$\mathcal{L}_{\text{box}}(b_i, \hat{b}_{\sigma(i)}) = \lambda_{\text{L1}} \| b_i - \hat{b}_{\sigma(i)} \|_1 + \lambda_{\text{giou}} \mathcal{L}_{\text{GIoU}}(b_i, \hat{b}_{\sigma(i)})$$

where $\lambda_{\text{L1}} = 5, \lambda_{\text{giou}} = 2$.

## 8. Training Procedure
- **Auxiliary Decoding Losses:** Applies auxiliary losses after every intermediate Transformer decoder layer ($L=1 \dots 5$) to improve gradient flow.
- **Optimizer:** AdamW with base learning rate $1 \times 10^{-4}$ for Transformer and $1 \times 10^{-5}$ for CNN backbone. Weight decay $1 \times 10^{-4}$.
- **Long Training Schedule:** Requires 500 epochs on COCO to reach convergence (due to slow global cross-attention learning).

## 9. PyTorch Implementation
Here is a complete, self-contained PyTorch implementation of DETR's **Hungarian Bipartite Matcher and Set Loss**.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from scipy.optimize import linear_sum_assignment

class HungarianMatcher(nn.Module):
    def __init__(self, cost_class=1.0, cost_bbox=5.0, cost_giou=2.0):
        super().__init__()
        self.cost_class = cost_class
        self.cost_bbox = cost_bbox
        self.cost_giou = cost_giou

    @torch.no_grad()
    def forward(self, pred_logits, pred_boxes, gt_classes, gt_boxes):
        """
        pred_logits: (B, N, K+1)
        pred_boxes:  (B, N, 4) in (cx, cy, w, h)
        gt_classes:  List of Tensors of length B
        gt_boxes:    List of Tensors of length B
        """
        B, N, _ = pred_logits.shape
        indices = []
        
        for i in range(B):
            out_prob = pred_logits[i].softmax(-1) # (N, K+1)
            out_bbox = pred_boxes[i]               # (N, 4)
            
            tgt_ids = gt_classes[i] # (N_gt,)
            tgt_bbox = gt_boxes[i]  # (N_gt, 4)
            
            if len(tgt_ids) == 0:
                indices.append((torch.empty(0, dtype=torch.int64), torch.empty(0, dtype=torch.int64)))
                continue
                
            # Class cost: -prob of true target class
            cost_class = -out_prob[:, tgt_ids] # (N, N_gt)
            
            # L1 Box cost
            cost_bbox = torch.cdist(out_bbox, tgt_bbox, p=1) # (N, N_gt)
            
            # Total Cost Matrix
            C = self.cost_class * cost_class + self.cost_bbox * cost_bbox
            C = C.cpu().numpy()
            
            # Hungarian algorithm matching
            src_ind, tgt_ind = linear_sum_assignment(C)
            indices.append((torch.as_tensor(src_ind, dtype=torch.int64), torch.as_tensor(tgt_ind, dtype=torch.int64)))
            
        return indices

if __name__ == "__main__":
    B, N, K = 2, 100, 80
    matcher = HungarianMatcher()
    
    pred_logits = torch.randn(B, N, K + 1)
    pred_boxes = torch.rand(B, N, 4)
    
    gt_classes = [torch.tensor([1, 5, 10]), torch.tensor([20])]
    gt_boxes = [torch.rand(3, 4), torch.rand(1, 4)]
    
    indices = matcher(pred_logits, pred_boxes, gt_classes, gt_boxes)
    
    print(f"Matched Pairs Batch 0: {len(indices[0][0])} queries matched to {len(gt_classes[0])} GT objects")
    assert len(indices[0][0]) == 3
    assert len(indices[1][0]) == 1
    print("DETR Hungarian Matcher verification successful!")
```

## 10. Strengths
- **Fully End-to-End Architecture:** Eliminates NMS, anchor generation, and spatial grid heuristics completely.
- **Global Context Reasoning:** Self-attention over full image memories prevents duplicate predictions natively.
- **Extensible to 3D & Video:** Direct set prediction simplifies extension to 3D detection and video tracking.

## 11. Weaknesses
- **Slow Training Convergence:** Requires 500 epochs ($\sim 4\times$ longer than Faster R-CNN) to learn sparse cross-attention maps.
- **Poor Small Object Accuracy:** Lacks multi-scale feature pyramids in original design; $32\times$ downsampling erases small objects.

## 12. Research Evolution
DETR opened the floodgates for Transformer object detection. It directly led to **Deformable DETR** (which added multi-scale deformable attention for $10\times$ faster convergence) and **RT-DETR** (real-time DETR).

## 13. Interview Questions

**Q1: How does DETR eliminate the need for Non-Maximum Suppression (NMS)?**
**A1:** DETR uses Hungarian Bipartite Matching loss during training, which enforces a strict 1-to-1 match between predictions and ground-truth objects. If two queries predict the same physical object, one is assigned to the object and the other is assigned to the "No-Object" background class, forcing the model to natively output non-overlapping predictions.

**Q2: What are Object Queries in DETR?**
**A2:** Object Queries are $N=100$ learned, trainable positional vectors fed into the Transformer decoder. Each query acts as a slot that learns to search for objects in specific regions/scales of the image via cross-attention over encoded image features.

**Q3: Why does DETR require 500 epochs to train compared to Faster R-CNN's 36 epochs?**
**A3:** In early training, cross-attention maps are uniform (every query attends to every pixel equally). It takes hundreds of epochs for object queries to learn localized spatial attention weights that focus on specific object boundaries.

**Q4: Explain the components of the Hungarian matching cost matrix.**
**A4:** $C_{i,j} = -\alpha \cdot \hat{p}_i(c_j) + \beta \cdot \|b_i - b_j^{\text{gt}}\|_1 + \gamma \cdot \mathcal{L}_{\text{GIoU}}(b_i, b_j^{\text{gt}})$. It combines class probability, $L_1$ box distance, and GIoU loss.

**Q5: What happens when an image contains fewer objects (e.g., 3 objects) than the number of DETR queries ($N=100$)?**
**A5:** The Hungarian matcher matches 3 queries to the ground-truth objects. The remaining 97 queries are matched to padded "No-Object" background targets $\emptyset$, receiving classification loss to output the background class.
