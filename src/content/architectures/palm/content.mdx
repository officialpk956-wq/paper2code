# PaLM

## 1. Overview
PaLM (Pathways Language Model), announced by Google Research in April 2022 (Chowdhery et al.), was Google's first massive counter-offensive to OpenAI's GPT-3. Scaling an autoregressive transformer to 540 Billion parameters, PaLM was not just a model, but a proof-of-concept for **Pathways**, Google's revolutionary new ML system design. Training a 540B parameter model is a logistical nightmare; if a single TPU fails, the entire run crashes. The Pathways infrastructure allowed Google to seamlessly train a single model across two separate TPU v4 pods (totaling 6,144 TPUs) connected over a datacenter network with extreme efficiency. PaLM achieved state-of-the-art few-shot performance on hundreds of natural language, reasoning, and code tasks. Crucially, it popularized the concept of **Chain-of-Thought (CoT) reasoning**. The researchers discovered that at the 540B scale, if the prompt provided an example of step-by-step logic, the model could solve highly complex mathematical and physics problems that it completely failed at when prompted normally, proving that scale unlocks entirely new tiers of emergent algorithmic logic.

:::tip
PaLM established that "Chain-of-Thought" prompting (e.g., adding "Let's think step by step") is not just a neat trick, but an emergent property of scale. If you are using a model smaller than ~60B parameters, CoT prompting often hurts performance. With models larger than 100B, it drastically improves it.
:::

## 2. Historical Context
By early 2022, the "Scaling Laws" hypothesis established by OpenAI's GPT-3 (2020) was the dominant philosophy in AI: larger models trained with more compute get predictably smarter. Google, having invented the Transformer in 2017, was widely perceived to be falling behind OpenAI in deploying massive, generalized models. While Google had internally developed massive models like Gopher and LaMDA, they needed a unified system that could scale compute far beyond a single supercomputer cluster. Jeff Dean introduced the "Pathways" vision—a single AI system that could generalize across thousands of tasks and modalities. PaLM was the first realization of this vision. By successfully orchestrating 6,144 TPU v4 chips across multiple data centers to train a dense 540 Billion parameter model, Google proved they possessed unparalleled hardware and distributed systems engineering. The resulting model didn't just beat GPT-3; its breakthrough in Chain-of-Thought reasoning shifted the entire industry's focus from mere text generation to complex agentic problem-solving.

## 3. Problem It Solves
PaLM solves the **Hardware Scale Bottleneck** and the **Multi-step Logic Failure** problem. Before PaLM, training models over 200B parameters (like Megatron-Turing NLG) was highly inefficient. The communication overhead between thousands of GPUs/TPUs meant that most of the time was spent waiting for data transfers, not doing actual math. The Pathways system solved this via a novel asynchronous client-server architecture, allowing PaLM to achieve a staggering 57.8% hardware FLOPs utilization, making massive-scale training economically viable. Secondly, standard LLMs act like intuition engines; they try to guess the answer instantly. If you ask GPT-3 a complex math problem, it guesses the final number and gets it wrong. PaLM solved this via Chain-of-Thought. By prompting the model to generate the intermediate mathematical steps *before* generating the final answer, PaLM uses the generated text as a temporary scratchpad, allowing it to solve multi-step constraints that defeat human-level intelligence tests.

## 4. Architecture Diagram Data

```text
   Input: "Q: If John has 5 apples, eats 2, and buys 4... A: Let's think..."

            |   +-----------------------------+   |

                               | (Distributed via Pathways)
                               |
             [ TPU v4 Pod A ] <=====> [ TPU v4 Pod B ]

```
**Components:**
- `PaLM Decoder`: A massive autoregressive transformer featuring specific architectural tweaks (SwiGLU, RoPE, Parallel layers) designed strictly for training stability at massive scale.
- `Parallel Formulation`: Unlike standard transformers where the FFN comes *after* the Attention layer, PaLM computes them in parallel to save communication overhead across TPUs.
- `Pathways / DCN`: The Datacenter Network. Pathways manages the asynchronous gradient updates across two physically separate TPU pods, masking the latency of the network transfer.
- `Chain of Thought`: The prompt explicitly begins with intermediate reasoning, triggering the model to utilize its massive capacity to calculate logic step-by-step.

## 5. Layer-by-Layer Breakdown
PaLM introduced several crucial architectural modifications to the standard Transformer to ensure a 540B model didn't suffer from gradient explosion or collapse during months of training.
1. **No Biases**: PaLM completely removes bias terms in all dense kernels and layer norms. This increases training stability for models over 100B parameters without harming performance.
2. **RoPE (Rotary Position Embeddings)**: Instead of absolute position embeddings (like GPT-3) or standard relative embeddings, PaLM uses RoPE, which injects relative positional information directly into the Attention Query and Key vectors via mathematical rotation, greatly improving generalization to longer sequences.
3. **Parallel Formulation**: In a standard block, $x_{next} = \text{FFN}(\text{Attn}(x))$. In PaLM, to increase speed and reduce communication across TPUs, they are computed simultaneously: $x_{next} = x + \text{Attn}(LN(x)) + \text{FFN}(LN(x))$.
4. **SwiGLU Activation**: Standard GELU or ReLU is replaced with Swish-GLU. GLU (Gated Linear Unit) architectures require three weight matrices instead of two in the FFN, but offer significantly better performance for the same compute budget.
5. **Multi-Query Attention (MQA)**: Instead of every attention head having its own Key and Value projection, all Query heads share a *single* Key and Value projection. This drastically reduces the memory bandwidth required for the KV-cache during autoregressive generation.

:::warning
Parallel Formulation provides a massive speedup during training because it allows the Attention and FFN matrices to be multiplied simultaneously. However, it slightly degrades the mathematical capacity of the layer compared to sequential processing, meaning you need a slightly larger model to achieve the same loss.
:::

## 6. Tensor Flow Walkthrough
Let's trace the shapes for a PaLM Parallel Transformer Block using Multi-Query Attention (MQA).
- `B`: Batch size
- `T`: Sequence length
- `D`: Hidden dimension (18,432)
- `H`: Number of Query heads (48)
- `D_h`: Head dimension (256)

1. **Input**: `x` shape `(B, T, D)`.
2. **Shared LayerNorm**: `normed_x = LayerNorm(x)`. Shape `(B, T, D)`.
3. **Parallel Processing**:
   - **MQA Path**:
     - `Q = Linear_Q(normed_x)`: Shape `(B, T, H * D_h)`.
     - `K = Linear_K(normed_x)`: Shape `(B, T, 1 * D_h)`. (Only ONE head!)
     - `V = Linear_V(normed_x)`: Shape `(B, T, 1 * D_h)`.
     - `Q` is split into `H` heads. `K` and `V` are broadcasted to match `H`.
     - Apply RoPE to `Q` and `K`.
     - `attn_out = Attention(Q, K, V)`. Shape `(B, T, D)`.
   - **SwiGLU FFN Path (Simultaneous)**:
     - `gate = Linear_gate(normed_x)`. Shape `(B, T, FFN_dim)`.
     - `up = Linear_up(normed_x)`. Shape `(B, T, FFN_dim)`.
     - `ffn_mid = Swish(gate) * up`.
     - `ffn_out = Linear_down(ffn_mid)`. Shape `(B, T, D)`.
4. **Residual Connection**:
   - `out = x + attn_out + ffn_out`. Shape `(B, T, D)`.

## 7. Mathematical Foundations
PaLM relies on the Rotary Position Embedding (RoPE) to handle sequence positions, and the SwiGLU activation for superior non-linear representations.

**RoPE (Rotary Position Embedding):**
Standard absolute embeddings $x + p$ degrade when the model encounters sequences longer than its training data. RoPE encodes absolute position with a rotation matrix and inherently incorporates relative position dependencies.
For a token embedding $x_m$ at position $m$, and query/key projections $W_q, W_k$, RoPE defines the query vector as:
$$ q_m = f_q(x_m, m) = (W_q x_m) e^{im\theta} $$
When computing the attention score between query at position $m$ and key at position $n$, the dot product elegantly becomes dependent *only* on the relative distance $m-n$:
$$ q_m \cdot k_n = (W_q x_m)^T (W_k x_n) \cos((m-n)\theta) $$
This mathematical trick (implemented via 2D rotation matrices) allows the model to extrapolate perfectly to sequence lengths it has never seen before.

**SwiGLU Activation:**
In a standard Transformer, the FFN is $W_2(\text{ReLU}(W_1 x))$.
PaLM uses SwiGLU, a variant of the Gated Linear Unit. It uses three matrices ($W, V, W_2$) and the Swish activation function ($\text{Swish}(x) = x \cdot \sigma(\beta x)$).
$$ \text{SwiGLU}(x, W, V, W_2) = (\text{Swish}(x W) \otimes x V) W_2 $$
The element-wise multiplication ($\otimes$) of the Swish-gated branch and the linear branch provides a dynamic gating mechanism, allowing the network to explicitly suppress irrelevant information, resulting in lower perplexity than standard GELU at the same parameter count.

## 8. Training Procedure
1. **The Pathways System**: Training a 540B model requires splitting the model across thousands of chips. Standard Megatron-Turing approaches split the model heavily using Pipeline Parallelism (putting layer 1 on GPU A, layer 2 on GPU B), which is slow due to network bubbles. Pathways uses extreme Data and Tensor parallelism across two entirely separate TPU v4 pods. The asynchronous gradients were sent over the DCN (Data Center Network), achieving 57.8% hardware utilization—an unprecedented feat of distributed engineering.
2. **Dataset**: PaLM was trained on 780 Billion tokens. The dataset was 78% English text (filtered web pages, books, Wikipedia), 22% non-English text (over 100 languages), and 5% code (GitHub).
3. **Emergence**: The authors formally studied "Emergent Abilities." They evaluated PaLM at 8B, 62B, and 540B parameters. They proved mathematically that performance on complex reasoning tasks (like BIG-bench) is not linear. At 8B and 62B, the model scores 0%. At 540B, the performance suddenly spikes to 60%. This proved that certain intellectual capabilities only "unlock" once a model reaches a critical mass of parameters.

## 9. PyTorch Implementation
Here is a conceptual implementation of the PaLM Parallel block with Multi-Query Attention (MQA) and SwiGLU.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class SwiGLU(nn.Module):
    def __init__(self, d_model: int, hidden_dim: int):
        super().__init__()
        # PaLM uses no biases
        self.w_gate = nn.Linear(d_model, hidden_dim, bias=False)
        self.w_up = nn.Linear(d_model, hidden_dim, bias=False)
        self.w_down = nn.Linear(hidden_dim, d_model, bias=False)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        gate = F.silu(self.w_gate(x)) # SiLU is Swish with beta=1
        up = self.w_up(x)
        return self.w_down(gate * up)

class PaLMParallelBlock(nn.Module):
    def __init__(self, d_model: int, n_heads: int):
        super().__init__()
        self.d_model = d_model
        self.n_heads = n_heads
        self.head_dim = d_model // n_heads
        
        # Shared LayerNorm (No bias/scale in PaLM, just normalization)
        # Using standard LayerNorm here for simplicity without affine parameters
        self.ln = nn.LayerNorm(d_model, elementwise_affine=False)
        
        # MQA: Q has n_heads, K and V have 1 head
        self.q_proj = nn.Linear(d_model, d_model, bias=False)
        self.k_proj = nn.Linear(d_model, self.head_dim, bias=False)
        self.v_proj = nn.Linear(d_model, self.head_dim, bias=False)
        self.o_proj = nn.Linear(d_model, d_model, bias=False)
        
        # SwiGLU FFN (Typically hidden_dim is 4/3 * 4 * d_model in GLU variants)
        self.ffn = SwiGLU(d_model, int(d_model * 4 * 2 / 3))

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B, T, D = x.shape
        normed_x = self.ln(x)
        
        # --- MQA Attention Branch ---
        q = self.q_proj(normed_x).view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
        # K and V have only 1 head. Shape: (B, 1, T, head_dim)
        k = self.k_proj(normed_x).view(B, T, 1, self.head_dim).transpose(1, 2)
        v = self.v_proj(normed_x).view(B, T, 1, self.head_dim).transpose(1, 2)
        
        # Broadcast K and V to match Q's heads during dot product
        # (In practice, specialized CUDA kernels do this to save memory)
        scores = torch.matmul(q, k.transpose(-2, -1)) / (self.head_dim ** 0.5)
        
        # Causal mask
        mask = torch.triu(torch.ones(T, T, device=x.device), diagonal=1).bool()
        scores.masked_fill_(mask, float('-inf'))
        
        attn_weights = F.softmax(scores, dim=-1)
        context = torch.matmul(attn_weights, v) # (B, n_heads, T, head_dim)
        context = context.transpose(1, 2).contiguous().view(B, T, D)
        attn_out = self.o_proj(context)
        
        # --- FFN Branch ---
        ffn_out = self.ffn(normed_x)
        
        # --- Parallel Residual ---
        return x + attn_out + ffn_out

# --- Shape Verification Test ---
if __name__ == "__main__":
    BATCH_SIZE, SEQ_LEN = 2, 32
    D_MODEL, N_HEADS = 512, 8
    
    block = PaLMParallelBlock(D_MODEL, N_HEADS)
    x = torch.randn(BATCH_SIZE, SEQ_LEN, D_MODEL)
    
    output = block(x)
    
    expected_shape = (BATCH_SIZE, SEQ_LEN, D_MODEL)
    assert output.shape == expected_shape, f"Shape mismatch! Expected {expected_shape}, got {output.shape}"
    print("Test passed! PaLM Parallel Block with MQA executed successfully.")
```

## 10. Strengths
PaLM's ultimate strength is its sheer capacity for reasoning, unlocked via its 540 Billion parameter scale. It popularized Chain-of-Thought (CoT) prompting, proving that if a model is large enough, asking it to explain its work step-by-step drastically reduces hallucinations and solves logic puzzles that defeat smaller models. Secondly, the architectural decisions (MQA, SwiGLU, Parallel layers, no biases) created an incredibly stable, highly efficient framework for distributed training and inference. Multi-Query Attention (MQA), in particular, was a massive breakthrough for inference speed. Because K and V only have one head, the memory required to store the KV-cache during token generation is reduced by a factor of the number of heads (e.g., 48x less memory), drastically increasing the batch size that a single GPU can serve in production without significantly harming the model's intelligence.

## 11. Weaknesses
PaLM is completely impractical for almost anyone outside of Google to run. At 540 Billion parameters, loading the model in 16-bit precision requires over 1 Terabyte of VRAM. That equates to roughly 14 Nvidia A100 (80GB) GPUs just to hold the weights in memory, making open-source deployment or fine-tuning impossible for average enterprises. Furthermore, while the Pathways system was a logistical marvel, the underlying training recipe was highly inefficient. Shortly after PaLM was released, DeepMind published the Chinchilla paper, proving that a 540B parameter model should theoretically be trained on roughly 11 Trillion tokens to be "compute-optimal." PaLM was only trained on 780 Billion tokens. This means PaLM is massively "under-trained"—it has too many parameters and not enough data, making it unnecessarily slow and expensive for the level of intelligence it achieved.

## 12. Research Evolution
PaLM was Google's flex of pure hardware and systems engineering dominance. It proved that the Transformer could be scaled cleanly to half a trillion parameters across distinct data centers, and it cemented Chain-of-Thought as the standard for interacting with Foundation Models. However, the scientific revelation of Chinchilla (that data must scale proportionally with parameters) rendered the 540B PaLM architecture obsolete almost immediately. Google recognized this inefficiency. Instead of trying to deploy the 540B monolith as their primary API, they merged the Google Brain and DeepMind teams and utilized the Chinchilla scaling laws to create PaLM 2—a model that was significantly smaller in parameter count, but trained on vastly more data, resulting in a faster, cheaper, and strictly superior successor.

## 13. Interview Questions
**Q1: What is "Chain-of-Thought" (CoT) prompting, and why did PaLM popularize it?**
**A1:** CoT prompting involves providing the model with a few examples of step-by-step reasoning (e.g., "First, multiply 5 by 2. Then add 3...") before asking for the answer. PaLM popularized this because the researchers proved that CoT only works on models larger than ~100B parameters. At 540B, PaLM used CoT to achieve state-of-the-art results on logic and math benchmarks that previously seemed impossible for language models.

**Q2: What is Multi-Query Attention (MQA), and why does it speed up inference?**
**A2:** In standard Multi-Head Attention, every Query head has a corresponding Key and Value head. During autoregressive generation, past K and V vectors must be stored in memory (KV-cache). In MQA, all Query heads share a *single* Key and Value head. This drastically shrinks the memory footprint of the KV-cache, allowing the GPU to serve much larger batch sizes and generate text much faster.

**Q3: How does the "Parallel Formulation" of the Transformer block work in PaLM?**
**A3:** In a standard block, the output is sequential: `x = x + Attn(x)`, then `x = x + FFN(x)`. In PaLM's parallel block, the input is passed to both sublayers simultaneously: `x = x + Attn(x) + FFN(x)`. This allows the massive matrix multiplications for Attention and FFN to be computed in parallel across TPUs, reducing communication latency by roughly 15%.

**Q4: Why did PaLM completely remove biases from all dense layers and LayerNorms?**
**A4:** Removing biases has been shown empirically to drastically improve training stability for models exceeding 100 Billion parameters. It prevents certain activations from exploding or drifting during the millions of steps required for pre-training, without sacrificing any measurable predictive performance.

**Q5: What was the primary inefficiency with PaLM's training recipe according to later research (Chinchilla)?**
**A5:** PaLM was massively under-trained. It had 540 Billion parameters but was trained on only 780 Billion tokens. Chinchilla scaling laws later proved that a model should be trained on roughly 20 tokens per parameter. Therefore, a 540B model should have been trained on 10.8 Trillion tokens. Because it wasn't, the model is bloated—it requires massive memory for inference but didn't see enough data to maximize the utility of those parameters.
