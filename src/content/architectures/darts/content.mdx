# DARTS
## 1. Overview
DARTS (Differentiable Architecture Search), introduced by Hanxiao Liu, Karen Simonyan, and Yiming Yang in 2018, completely revolutionized the field of Neural Architecture Search (NAS). Previous methods, like NASNet, used Reinforcement Learning (RL) or Evolutionary Algorithms to search for architectures. Because those methods treat the architecture as a discrete set of choices (e.g., "Choose a $3 \times 3$ filter or a $5 \times 5$ filter"), they could not use standard gradient descent. The result was a catastrophically slow search process, requiring thousands of GPU-days to evaluate tens of thousands of candidate models independently.

DARTS proposed a brilliant, mathematically elegant solution: **Continuous Relaxation**. Instead of forcing the network to choose *one* operation discretely, DARTS places *all possible operations* on every single edge of the network and weights them using a softmax function. Because the weights are continuous, the entire architecture search space becomes differentiable. DARTS can simultaneously train both the network weights and the architectural weights using standard gradient descent (backpropagation) on a single "Super-Network." This reduced the cost of discovering state-of-the-art architectures from 2000 GPU-days (NASNet) to roughly **1 GPU-day**, democratizing NAS for researchers worldwide.

## 2. Historical Context
By 2018, NASNet had proven that machines could design better Convolutional Neural Networks than humans. However, the RL-based search process developed by Google required massive computing clusters (500 GPUs running for 4 days). This meant only massive tech giants could afford to research and design new architectures.

The community frantically searched for ways to make NAS cheaper. ENAS (Efficient NAS) made a major breakthrough by forcing all child networks to share weights, reducing search time to about 1 GPU-day, but it still relied on RL controllers sampling discrete architectures. 

The DARTS authors (from CMU and DeepMind) realized that RL was the wrong tool for the job. RL is required when the reward surface is non-differentiable (like playing chess or sampling discrete categories). But neural networks are fundamentally built on gradient descent. If they could figure out a way to make the *choice* of an architecture continuous rather than discrete, they could throw away the RL controller entirely and use standard backpropagation to find the architecture. Their continuous relaxation formula was the key to this breakthrough.

## 3. Problem It Solves
The core problem DARTS solves is the massive computational inefficiency of searching over a discrete, non-differentiable architectural space.

**1. The Discrete Search Problem (RL/Evolution):**
In a NASNet-style search space, an edge between two nodes can contain exactly one operation from a predefined set $\mathcal{O}$ (e.g., $3 \times 3$ Conv, MaxPool, Zero/None). To evaluate an architecture, the RL agent must sample one discrete operation, build the network, train it from scratch, and evaluate it. This is a black-box optimization problem, heavily relying on trial and error.

**2. The Continuous Relaxation Solution (DARTS):**
DARTS solves this by placing *every single operation* in $\mathcal{O}$ on every edge simultaneously in a massive "Super-Network". 
Instead of a discrete choice, the output of an edge is a weighted sum of all possible operations. The weights (called $\alpha$) are continuous variables parameterized by a softmax.
Because everything is now continuous and connected, you simply feed data into the Super-Network and backpropagate the loss. The gradients will naturally increase the $\alpha$ weights of operations that minimize the loss (e.g., the $3 \times 3$ Conv) and decrease the weights of useless operations (e.g., Zero).
Once training is done, you simply look at the $\alpha$ weights and pick the operation with the highest weight for each edge, collapsing the Super-Network into a final, discrete architecture.

## 5. Layer-by-Layer Breakdown
Like NASNet, DARTS searches for a **Normal Cell** and a **Reduction Cell**. A Cell is a directed acyclic graph (DAG) consisting of an ordered sequence of nodes.

1.  **Nodes**: Each cell has two input nodes (outputs from previous cells), a set of intermediate nodes, and a single output node (the concatenation of all intermediate nodes).
2.  **Edges (Super-Network)**: During the search phase, every intermediate node receives input from *all* previous nodes in the cell. Every single edge contains a mixture of all candidate operations (e.g., $3 \times 3$ separable conv, $3 \times 3$ dilated conv, $3 \times 3$ max pool, $3 \times 3$ average pool, identity, and zero).
3.  **Forward Pass**: The data flows through all operations simultaneously. The output of an edge is the softmax-weighted sum of all operation outputs.
4.  **Bilevel Optimization**: DARTS optimizes two sets of weights simultaneously:
    *   **Network Weights ($w$)**: The actual convolution filters. Trained on the *Training Dataset*.
    *   **Architecture Weights ($\alpha$)**: The softmax weights determining which operation is best. Trained on the *Validation Dataset* to prevent the architecture from simply overfitting the training data.
5.  **Discretization**: Once the search converges, the continuous Super-Network is discretized. For each intermediate node, DARTS keeps only the two strongest incoming edges (based on $\alpha$ values), and on those edges, keeps only the single operation with the highest $\alpha$ weight. The rest are discarded.

## 7. Mathematical Foundations
The genius of DARTS lies entirely in Section 2.1 of the paper: Continuous Relaxation.

Let $\mathcal{O}$ be a set of candidate operations (e.g., convolution, max pooling, zero) to be applied to an input $x$. 
In discrete NAS, the edge calculates $o(x)$ for some exactly chosen $o \in \mathcal{O}$.

To make the search space continuous, DARTS introduces a set of architecture mixing weights $\alpha^{(i,j)}$ for the directed edge connecting node $i$ to node $j$. The discrete choice is relaxed to a continuous softmax-weighted sum of all operations in $\mathcal{O}$:

$$\bar{o}^{(i,j)}(x) = \sum_{o \in \mathcal{O}} \frac{\exp(\alpha_o^{(i,j)})}{\sum_{o' \in \mathcal{O}} \exp(\alpha_{o'}^{(i,j)})} o(x)$$

Where:
*   $x$ is the input from node $i$.
*   $\bar{o}^{(i,j)}(x)$ is the continuous, mixed output flowing to node $j$.
*   $\alpha_o^{(i,j)}$ is the unnormalized architectural weight (parameter) for operation $o$ on edge $(i, j)$.
*   The fraction is the softmax function, ensuring the weights sum to 1.

Because this formula is completely differentiable with respect to both the operation weights $w$ (inside $o(x)$) and the architecture weights $\alpha$, we can solve a **bilevel optimization problem**:
1.  Find the optimal network weights $w^*$ by minimizing the training loss $\mathcal{L}_{train}(w, \alpha^*)$.
2.  Find the optimal architecture weights $\alpha^*$ by minimizing the validation loss $\mathcal{L}_{val}(w^*, \alpha)$.

In practice, DARTS approximates this by alternating gradient descent steps: one step updating $w$ using training data, followed by one step updating $\alpha$ using validation data.

## 8. Training Procedure
The DARTS pipeline has two stages, mirroring NASNet but executing significantly faster.

**1. Search Phase (The Super-Network)**:
*   **Dataset**: CIFAR-10.
*   **Setup**: A small Super-Network (8 cells) is constructed where every edge contains the continuous relaxation sum of all 8 candidate operations.
*   **Training**: Alternating gradient descent. Update network weights $w$ on a batch of training data. Update architecture weights $\alpha$ on a batch of validation data.
*   **Time**: Converges in about 50 epochs (roughly **1.5 GPU-days** on a single GTX 1080 Ti).

**2. Evaluation Phase (The Discretized Network)**:
*   **Discretization**: The continuous Super-Network is pruned to create the final, discrete Normal and Reduction cells.
*   **Dataset**: ImageNet (or CIFAR).
*   **Training**: A massive macro-architecture (e.g., 14 cells) is built from the discovered discrete cells. The network is trained from scratch for 250 epochs using standard techniques (SGD, auxiliary towers, Cutout, DropPath). The $\alpha$ weights are discarded; only the standard network weights $w$ are trained.

## 9. PyTorch Implementation
Here is a concise implementation of a single DARTS Mixed Edge (the Continuous Relaxation).

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class DARTSMixedOp(nn.Module):
    # Implements the Continuous Relaxation formula for a single edge
    
    def __init__(self, C, stride):
        super(DARTSMixedOp, self).__init__()
        self.ops = nn.ModuleList()
        
        # Define the candidate operation set O
        # 1. 3x3 Conv
        self.ops.append(nn.Sequential(
            nn.Conv2d(C, C, 3, stride=stride, padding=1, bias=False),
            nn.BatchNorm2d(C)
        ))
        
        # 2. 3x3 MaxPool
        self.ops.append(nn.MaxPool2d(3, stride=stride, padding=1))
        
        # 3. Identity (Skip Connect) - Only valid if stride == 1
        if stride == 1:
            self.ops.append(nn.Identity())
        else:
            # If downsampling, identity must be replaced by a strided operation
            self.ops.append(nn.Sequential(
                nn.AvgPool2d(2, stride=2),
                nn.Conv2d(C, C, 1, bias=False),
                nn.BatchNorm2d(C)
            ))
            
        # 4. Zero (No connection)
        # Implemented inline in forward pass by multiplying by 0

    def forward(self, x, weights):
        # weights is the softmaxed alpha tensor of shape (4,) for the 4 operations
        # Formula: sum( weight_i * op_i(x) )
        
        # Compute the outputs for the 3 active operations
        op0_out = self.ops[0](x)
        op1_out = self.ops[1](x)
        op2_out = self.ops[2](x)
        
        # The 4th operation is Zero, which outputs a tensor of zeros. 
        # weight_3 * 0 = 0, so we don't need to compute it.
        
        # Multiply by architectural weights and sum
        out = (weights[0] * op0_out) + (weights[1] * op1_out) + (weights[2] * op2_out) 
        
        return out

# --- Shape Verification Test ---
if __name__ == '__main__':
    # Initialize the mixed operation (Input channels: 32, Stride: 1)
    model = DARTSMixedOp(C=32, stride=1)
    
    dummy_input = torch.randn(2, 32, 28, 28)
    
    # Simulate the architecture weights (alpha). 
    # Assume the softmax has already been applied, giving 4 probabilities.
    dummy_alphas = torch.tensor([0.6, 0.2, 0.1, 0.1])
    
    output = model(dummy_input, dummy_alphas)
    
    print(f"Input shape:  {dummy_input.shape}")
    print(f"Output shape: {output.shape}")
    
    assert output.shape == (2, 32, 28, 28), "Output shape is incorrect!"
    print("Shape verification passed.")
```

## 10. Strengths
*   **Monumental Speedup**: By transforming NAS from a black-box RL problem into a differentiable gradient-based problem, DARTS reduced search time by three orders of magnitude (2000 GPU-days to 1 GPU-day).
*   **Simplicity**: The algorithm is remarkably elegant and mathematically clean. It requires no complex RL controllers, policy gradients, or hypernetworks. It simply uses standard PyTorch/TensorFlow backpropagation on a larger graph.
*   **High Accuracy**: Despite the massive speedup, the architectures discovered by DARTS matched or slightly exceeded the accuracy of those found by the astronomically expensive NASNet search.

## 11. Weaknesses
*   **The Depth Gap (Performance Collapse)**: DARTS searches on a "shallow" 8-cell Super-Network but evaluates on a "deep" 14-cell network. The continuous relaxation introduces a bias: operations with fewer weights (like Identity or MaxPool) converge faster early in the search than deep convolutions. This often causes DARTS to collapse, picking too many Identity connections and producing degenerate, poorly performing final architectures (a widely studied problem known as the "DARTS collapse").
*   **Memory Intensive Search**: During the search phase, the Super-Network must hold the feature maps and gradients for *every* candidate operation on *every* edge simultaneously in GPU VRAM. This limits the search to small batch sizes, small networks, and a small candidate operation set (usually $\leq 8$ ops) before causing Out-Of-Memory (OOM) errors.

## 12. Research Evolution
DARTS was arguably the most impactful NAS paper since the original NASNet. It spawned an entire sub-field of "Differentiable Architecture Search".

However, the weaknesses of DARTS—specifically the VRAM consumption and the performance collapse—became the immediate focus of the community. 
*   **PC-DARTS (Partially-Connected DARTS)** solved the VRAM issue by only feeding a random subset of channels into the mixed operations, allowing for larger batch sizes and deeper search networks.
*   **FairDARTS** solved the performance collapse by replacing the competitive Softmax function with independent Sigmoid functions, preventing the "Identity" operation from unfairly starving the convolutions of architectural weight during the early search phase.

## 13. Interview Questions

**Q1: What is the fundamental difference between how NASNet and DARTS search for an architecture?**
**A1:** NASNet treats architecture search as a discrete problem. It uses a Reinforcement Learning agent to propose a distinct architecture, trains it, and uses the final accuracy as a reward. This is non-differentiable and incredibly slow. DARTS treats architecture search as a continuous problem. It places all possible operations on every edge simultaneously, weights them using a softmax function, and uses standard gradient descent to learn which operations minimize the loss, making it orders of magnitude faster.

**Q2: Explain the Continuous Relaxation formula in DARTS.**
**A2:** The continuous relaxation formula replaces a discrete choice of a single operation with a weighted sum of all possible operations in a set $\mathcal{O}$. For a given input $x$, the output of an edge is $\sum_{o \in \mathcal{O}} \text{softmax}(\alpha_o) \cdot o(x)$. The parameters $\alpha$ are the "architecture weights" that the network learns via backpropagation.

**Q3: How does DARTS discretize the continuous Super-Network into a final, usable neural network?**
**A3:** Once the search phase concludes and the optimal $\alpha$ weights are found, the continuous graph is pruned. For every intermediate node, DARTS looks at all incoming edges and keeps only the two edges with the highest maximum $\alpha$ weights. On those two edges, it selects the single operation $o$ that has the highest $\alpha_o$ weight, discarding all other operations (including the Zero operation).

**Q4: DARTS optimizes two sets of weights (network weights $w$ and architecture weights $\alpha$). Why does it train them on different datasets?**
**A4:** DARTS frames NAS as a bilevel optimization problem. The network weights $w$ (the convolution filters) are updated using the *training* dataset to minimize the training loss. The architecture weights $\alpha$ are updated using the *validation* dataset. If both were trained on the training data, the architecture would simply overfit, choosing operations that perfectly memorize the training set but generalize poorly.

**Q5: What is the primary hardware limitation of the DARTS search phase?**
**A5:** GPU Memory (VRAM) consumption. Because the Super-Network calculates the forward and backward passes for *every* candidate operation on *every* edge simultaneously, the memory footprint is massive. This severely limits the size of the operation set $\mathcal{O}$ and the depth of the network that can be searched on a standard GPU.
