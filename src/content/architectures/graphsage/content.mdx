# GraphSAGE

## 1. Overview
GraphSAGE (Sample and Aggregate), introduced in 2017 by William L. Hamilton, Rex Ying, and Jure Leskovec (Stanford University), revolutionized Graph Neural Networks by introducing **Inductive Representation Learning on Large Graphs**. Prior to GraphSAGE, standard Graph Convolutional Networks (GCNs) were strictly transductive: training required loading the entire graph adjacency matrix into GPU memory simultaneously, making it impossible to scale to graphs with millions of nodes or generate embeddings for newly arriving unseen nodes without re-training the full network. GraphSAGE solved this by shifting the paradigm from learning static node embedding lookups to learning **Generalized Aggregator Functions**. GraphSAGE samples a fixed-size local neighborhood $S_{\mathcal{N}(v)}$ for each node (e.g., 25 1-hop neighbors, 10 2-hop neighbors) and aggregates features using flexible functions (Mean, LSTM, or Pooling aggregators). This enables mini-batch SGD training on massive multi-million node graphs and instant inductive generalization to completely unseen nodes.

:::note
GraphSAGE concept: "Inductive GNN framework learning generalized aggregator functions (Mean, Pooling, LSTM) over uniform fixed-size sampled neighborhoods $S_{\mathcal{N}(v)}$, enabling mini-batch training and instant generalization to unseen nodes."
:::

## 2. Historical Context
In 2017, GCNs required evaluating full-graph propagation $H^{(l+1)} = \sigma(\tilde{A} H^{(l)} W^{(l)})$. In industrial production (e.g., Pinterest, Twitter), graphs grow continuously as new users and posts are created every second. Re-running $O(|V|^3)$ or $O(|V|)$ full-graph GCN passes for every new user was computationally impossible.

Hamilton, Ying, and Leskovec designed GraphSAGE to operate inductively. By training parameter matrices $(W^k, \text{Aggregator}_k)$ over local sampled neighborhoods rather than full adjacency matrices, GraphSAGE enabled mini-batch SGD and zero-shot inference on newly added nodes.

## 3. Problem It Solves
GraphSAGE resolves three primary limitations of early GNN models:
1. **Transductive Limitation (Inability to Generalize to Unseen Nodes):** Learns inductive aggregation functions that generate embeddings for brand new nodes introduced after training.
2. **Full-Graph Adjacency Memory Footprint:** Replaces full-graph adjacency multiplication with uniform fixed-size neighborhood sampling ($S_{\mathcal{N}(v)}$), enabling mini-batch SGD training.
3. **Restricted Aggregation Expressiveness:** Extends neighborhood aggregation beyond simple weighted sums to flexible architectures including **Mean Aggregators**, **Pooling Aggregators**, and **LSTM Aggregators**.

## 4. Architecture Diagram Data
Below is the GraphSAGE Inductive Neighborhood Sampling and Multi-Layer Feature Aggregation pipeline.

```text
       FULL GRAPH TOPOLOGY G = (V, E)
       Target Node v with 1-Hop & 2-Hop Neighborhoods
                           |
                           v
       +===================================================================+
       | 1. FIXED-SIZE UNIFORM NEIGHBORHOOD SAMPLING                       |
       | - Sample S_1 = 25 1-hop neighbors for target node v                |
       | - Sample S_2 = 10 2-hop neighbors for each 1-hop neighbor          |
       +===================================================================+
                           |
                           v
       +===================================================================+
       | 2. LAYER-BY-LAYER INDUCTIVE AGGREGATION                           |
       |                                                                   |
       | [ Step A: Aggregate Neighbor Representations ]                    |
       | h_{N(v)}^k = Aggregator_k( { h_u^{k-1}, forall u in S_{N(v)} } )  |
       |                                                                   |
       | [ Step B: Concatenate Target & Neighbor Aggregation ]             |
       | h_v^k = Activation( W^k * [ h_v^{k-1} || h_{N(v)}^k ] )            |
       |                                                                   |
       | [ Step C: L2 Normalization ]                                      |
       | h_v^k = h_v^k / ||h_v^k||_2                                       |
       +===================================================================+
                           |
                           v
       [ Output Node Embedding z_v = h_v^K in R^d ]
```

## 5. Layer-by-Layer Breakdown

**1. Neighborhood Sampling Layer:**
- At layer $k$, uniform random sampling selects a fixed size $S_k$ of neighbors for node $v$: $S_{\mathcal{N}(v)} \subset \mathcal{N}(v)$.
- Typical sampling sizes: $S_1 = 25$ for 1-hop, $S_2 = 10$ for 2-hop.

**2. Flexible Aggregator Architectures ($\text{AGGREGATE}_k$):**
- **Mean Aggregator:** Takes element-wise mean of neighbor feature vectors:
  $$h_{\mathcal{N}(v)}^k = \text{MEAN}\left( \{ h_u^{k-1}, \; \forall u \in S_{\mathcal{N}(v)} \} \right)$$
- **Pooling Aggregator (Max-Pooling MLP):** Passes neighbor vectors through an MLP followed by element-wise max-pooling:
  $$h_{\mathcal{N}(v)}^k = \max \left( \{ \text{ReLU}(W_{\text{pool}} h_u^{k-1} + b), \; \forall u \in S_{\mathcal{N}(v)} \} \right)$$
- **LSTM Aggregator:** Passes randomly shuffled neighbor sequences through an LSTM cell.

**3. Feature Concatenation & Transformation:**
- Concatenates node's own vector $h_v^{k-1}$ with neighbor message $h_{\mathcal{N}(v)}^k$:
  $$h_v^k = \sigma\left( W^k \cdot \left[ h_v^{k-1} \;\|\; h_{\mathcal{N}(v)}^k \right] \right)$$
- Normalizes output vector: $h_v^k = \frac{h_v^k}{\|h_v^k\|_2}$.

## 6. Tensor Flow Walkthrough
Let's trace tensors through GraphSAGE for batch size $B=512$ target nodes, 1-hop sample size $S_1=25$, feature dimension $d_0=128$, output dimension $d_1=256$.

1. **Sample Neighborhood Subgraph:**
   - Target Nodes: `(512, 128)`
   - 1-Hop Neighbor Features: `(512, 25, 128)`
2. **Mean Aggregation Step:**
   - Mean across neighbors $\to h_{\mathcal{N}(v)}$: `(512, 128)`
3. **Concatenation Step:**
   - Concat Target + Neighbor Message $[h_v, h_{\mathcal{N}(v)}] \to$ `(512, 256)`
4. **Linear Projection & $L_2$ Normalization:**
   - Linear Weight $W^k \to (512, 256) \xrightarrow{\text{ReLU}} \xrightarrow{L_2 \text{ Norm}} h_v^1$: `(512, 256)`.

## 7. Mathematical Foundations

### 1. General GraphSAGE Layer Propagation Algorithm
For layer $k = 1 \dots K$ and node $v \in V$:

$$h_{\mathcal{N}(v)}^k = \text{AGGREGATE}_k \left( \{ h_u^{k-1}, \; \forall u \in S_{\mathcal{N}(v)} \} \right)$$

$$h_v^k = \sigma \left( W^k \cdot \left[ h_v^{k-1} \;\Vert\; h_{\mathcal{N}(v)}^k \right] \right)$$

$$h_v^k = \frac{h_v^k}{\|h_v^k\|_2}$$

### 2. Unsupervised GraphSAGE Loss Function
When node labels are unavailable, GraphSAGE optimizes an unsupervised loss function encouraging nearby nodes to have similar representations while pushing distant nodes apart:

$$\mathcal{L}_{\text{graph}}(z_u) = -\log \sigma\left( z_u^T z_v \right) - Q \cdot \mathbb{E}_{v_n \sim P_n(v)} \left[ \log \sigma\left( -z_u^T z_{v_n} \right) \right]$$

where $v$ is a co-occurring neighbor of $u$, $v_n$ is a negative sample node, and $Q$ is the number of negative samples.

## 8. Training Procedure
- Sample mini-batch of target nodes $\mathcal{B}$.
- Recursively sample 1-hop ($S_1=25$) and 2-hop ($S_2=10$) neighborhoods for all batch nodes.
- Execute forward pass through $K=2$ GraphSAGE layers using Mean or Max-Pooling aggregators.
- Compute Supervised Cross-Entropy or Unsupervised Graph Loss $\mathcal{L}_{\text{graph}}$.
- Update weights $W^k$ and Aggregator parameters using Adam optimizer.

## 9. PyTorch Implementation
Here is a complete PyTorch implementation of the **GraphSAGE Pooling Aggregator Layer**.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class GraphSAGELayer(nn.Module):
    """ GraphSAGE Layer with Pooling Aggregator """
    def __init__(self, in_features, out_features, aggregator_type='mean'):
        super().__init__()
        self.aggregator_type = aggregator_type
        
        if aggregator_type == 'pooling':
            self.pool_mlp = nn.Sequential(
                nn.Linear(in_features, in_features),
                nn.ReLU()
            )
            
        self.w_k = nn.Linear(2 * in_features, out_features)

    def forward(self, target_feats, neighbor_feats):
        """
        target_feats:   (B, in_features)
        neighbor_feats: (B, S, in_features) S is sample size
        """
        if self.aggregator_type == 'mean':
            # Mean Aggregator
            h_neigh = neighbor_feats.mean(dim=1) # (B, in_features)
        elif self.aggregator_type == 'pooling':
            # Max-Pooling Aggregator
            pooled_neighbors = self.pool_mlp(neighbor_feats) # (B, S, in_features)
            h_neigh = pooled_neighbors.max(dim=1)[0]         # (B, in_features)
            
        # Concatenate Target Vector and Neighbor Message
        concat_feats = torch.cat([target_feats, h_neigh], dim=-1) # (B, 2 * in_features)
        
        # Linear Projection + Activation
        h_v = F.relu(self.w_k(concat_feats))
        
        # L2 Normalization
        h_norm = F.normalize(h_v, p=2, dim=-1)
        return h_norm

if __name__ == "__main__":
    B, S, in_dim, out_dim = 512, 25, 128, 256
    sage_layer = GraphSAGELayer(in_features=in_dim, out_features=out_dim, aggregator_type='pooling')
    
    target_x = torch.randn(B, in_dim)
    neighbor_x = torch.randn(B, S, in_dim)
    
    out_h = sage_layer(target_x, neighbor_x)
    
    print(f"GraphSAGE Node Embedding Shape: {out_h.shape}")
    assert out_h.shape == (B, out_dim)
    print("GraphSAGE verification successful!")
```

## 10. Strengths
- **Inductive Generalization:** Generates embeddings for newly created, unseen graph nodes in real time.
- **Scalable Mini-Batch SGD:** Uniform fixed-size neighborhood sampling ($S_k$) prevents memory explosion.
- **Flexible Aggregation Architecture:** Supports Mean, Max-Pooling, and LSTM aggregators.

## 11. Weaknesses
- **Information Loss from Uniform Sampling:** Uniform random neighborhood sampling can drop important hub nodes.

## 12. Research Evolution
GraphSAGE established inductive graph learning, directly leading to **PinSage**, **GAT**, and **FastGCN**.

## 13. Interview Questions

**Q1: What is the main difference between an Inductive GNN and a Transductive GNN?**
**A1:** Transductive GNNs (like standard GCN) require the full adjacency matrix of a fixed graph during training and cannot generate embeddings for unseen nodes without retraining. Inductive GNNs (like GraphSAGE) learn generalized aggregation functions over local sampled neighborhoods, allowing instant zero-shot inference on newly added nodes.

**Q2: How does GraphSAGE prevent the graph neighborhood explosion problem?**
**A2:** By using uniform fixed-size neighborhood sampling ($S_k$). Instead of aggregating all neighbors (which can be 100,000 for hub nodes), GraphSAGE uniformly samples a fixed size (e.g., $S_1=25, S_2=10$) for every node, keeping mini-batch tensor shapes constant.

**Q3: Write out the GraphSAGE concatenation propagation formula.**
**A3:** $h_v^k = \sigma\left( W^k \cdot [h_v^{k-1} \parallel h_{\mathcal{N}(v)}^k] \right)$, where $h_{\mathcal{N}(v)}^k$ is the aggregated message from sampled neighbors.

**Q4: Compare the Mean Aggregator and Max-Pooling Aggregator in GraphSAGE.**
**A4:** The **Mean Aggregator** computes a simple element-wise average over neighbor vectors. The **Max-Pooling Aggregator** passes neighbor vectors through a trainable MLP before applying element-wise max-pooling, allowing the network to capture complex non-linear neighborhood features.

**Q5: Why is $L_2$ Normalization applied to node vectors at the end of each GraphSAGE layer?**
**A5:** $L_2$ normalization forces all node representations onto a unit hypersphere ($\|h_v\|_2 = 1$), preventing vector magnitudes from exploding across deep aggregation layers and improving distance metric stability.
