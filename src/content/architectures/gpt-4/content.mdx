# GPT-4

## 1. Overview
GPT-4, officially announced by OpenAI in March 2023, represents the current pinnacle of the autoregressive Transformer lineage. Following the explosive mainstream success of ChatGPT (powered by GPT-3.5), OpenAI spent over a year developing GPT-4 to address the reasoning and reliability limits of its predecessors. GPT-4 is a massive leap forward in two distinct areas: **Complex Reasoning** and **Multimodality**. While GPT-3.5 could write essays and code, it failed at complex logic puzzles, advanced mathematics, and nuanced professional exams. GPT-4 dominates these benchmarks, passing the Uniform Bar Exam in the 90th percentile (compared to GPT-3.5's 10th percentile). Furthermore, GPT-4 is natively multimodal; it accepts images as input alongside text, allowing it to interpret charts, analyze photographs, and read diagrams with the same fluency it reads text. Behind closed doors, GPT-4 is widely believed to be a massive Sparse Mixture of Experts (MoE) architecture, though OpenAI notoriously published zero architectural details in the official technical report, marking a total shift from open science to closed commercial secrecy.

:::tip
GPT-4's massive leap in reasoning makes it the definitive model for complex agentic workflows. When building autonomous AI agents that must plan, reflect, and use external tools (like calculators or web browsers), GPT-4's ability to maintain logical consistency far outperforms any open-source alternative.
:::

## 2. Historical Context
To understand GPT-4's release, one must look back to 2019. When OpenAI released GPT-2, they famously declared it "too dangerous to release" in full, citing concerns that a 1.5B parameter model could be used for mass disinformation. They released it in staggered, smaller versions. By 2020, they released the GPT-3 paper with full architectural details, but kept the weights behind an API. When ChatGPT launched in 2022, it triggered a global AI arms race. By the time GPT-4 was ready in 2023, the landscape had changed entirely. AI was now a multi-trillion-dollar commercial battleground. Citing both the competitive landscape and extreme safety concerns regarding AI capabilities, OpenAI published the GPT-4 Technical Report—a 100-page document that explicitly stated they would release *zero* details about the architecture, parameter count, dataset, or training hardware. The evolution of safety concerns, from GPT-2's staggered release to GPT-4's total architectural blackout, reflects the industry's realization that foundation models are no longer just academic curiosities; they are immensely powerful, dual-use technologies with global economic and security implications.

## 3. Problem It Solves
GPT-4 solves the **Reasoning Ceiling** and the **Text-Only Bottleneck**. Previous models relied heavily on pattern matching. If you asked GPT-3 to solve a logic puzzle, it would generate text that sounded like a solution but was logically flawed because it couldn't reliably maintain state and constraints over long generations. GPT-4 was engineered specifically for "steerability" and deep reasoning. It solves complex coding problems, advanced calculus, and multi-step logic chains with unprecedented reliability. Secondly, the real world is not text-only. Humans interact with data through charts, UI layouts, and physical environments. By accepting image inputs natively into the Transformer architecture, GPT-4 allows developers to build systems that bridge the physical and digital worlds—for example, taking a photo of the inside of a refrigerator and having the model output a recipe based on the visible ingredients, or uploading a hand-drawn sketch of a website and having the model output the HTML/CSS code.

## 4. Architecture Diagram Data
```text
           [ GPT-4: Multimodal Mixture of Experts (Rumored) ]

   Image Input   Text Input (Prompt)
     [📸]         "Explain this."
       |                 |
   (CNN/ViT)        (Tokenizer)
       |                 |
       +-------+---------+
               |
      [ Joint Embedding Space ]
               |
   +-----------+-----------+
   |   Transformer Block   |
   |                       |
   |      [ Attention ]    |
   |            |          |
   |      [ MoE Router]    | ---> Selects 2 Experts out of 16
   |       /         \     |
   | [Expert 1] ... [Expert 16] (Feed-Forward Networks)
   +-----------+-----------+
               |
         (Output Text)
      "The chart shows..."
```
**Components:**
- `Image/Text Input`: GPT-4 processes both modalities. Images are likely passed through a Vision Transformer (ViT) and projected into the same dimensional space as the text tokens, allowing the core transformer to attend to both text and image patches simultaneously.
- `MoE Router (Rumored)`: Instead of a massive, monolithic Feed-Forward Network, GPT-4 is widely believed to use a Sparse Mixture of Experts. A router network looks at each token and sends it to only 2 of the 16 available expert networks.
- `Experts`: Specialized FFNs. This allows the total parameter count to be massive (rumored ~1.8 Trillion) for high capacity, while the *active* parameter count per token remains low (rumored ~220 Billion) to keep inference fast and affordable.

## 5. Layer-by-Layer Breakdown
*Note: Because OpenAI has not officially confirmed the architecture, this breakdown relies on widely accepted industry leaks and the technical trajectory of scaling laws.*
1. **Multimodal Input**: Text is tokenized (using the updated `cl100k_base` tiktoken vocabulary, which is much more efficient for code and non-English text). Images are broken into patches, encoded via a vision model, and interspersed with the text tokens.
2. **Context Window Expansion**: GPT-4 launched with an 8,192 token context window, quickly followed by a 32,768 token version, and eventually a 128,000 token version (GPT-4 Turbo). This requires highly optimized attention mechanisms (like FlashAttention) to handle the $O(N^2)$ memory scaling.
3. **Sparse Mixture of Experts (MoE)**: The core innovation over GPT-3. It is rumored to consist of 1.8 Trillion parameters divided across 16 experts. During the Feed-Forward phase of the transformer block, a routing mechanism assigns each token to only 2 experts.
4. **Alignment (RLHF & RBRMs)**: Following the InstructGPT pipeline, GPT-4 underwent massive RLHF. Crucially, they introduced Rule-Based Reward Models (RBRMs)—secondary AI models designed specifically to act as harsh judges, penalizing the RLHF process if it generated content that violated strict safety rules, resulting in a model that is much harder to "jailbreak" than GPT-3.5.

:::warning
Because of the rumored MoE architecture, GPT-4 can sometimes exhibit "expert routing failure" on highly ambiguous prompts, where the router sends the token to a suboptimal expert, resulting in a slight degrade in logic. Prompting clearly and explicitly ensures the router engages the correct neural pathways.
:::

## 6. Tensor Flow Walkthrough
Let's trace the shapes for a theoretical MoE forward pass (based on industry leaks).
- `B`: Batch size
- `T`: Sequence length
- `D`: Hidden dimension (e.g., 8192)
- `E`: Number of Experts (16)
- `K`: Number of active experts per token (2)

1. **Input**: `x` shape `(B, T, D)`.
2. **Self-Attention**: Standard multi-head attention. Output shape `(B, T, D)`.
3. **MoE Routing**:
   - The router applies a linear layer to determine expert affinities: `RouterLogits = Linear(x)`. Shape `(B, T, E)`.
   - `TopK_Indices, TopK_Weights = TopK(Softmax(RouterLogits), k=2)`.
   - Each token is now mapped to 2 specific experts.
4. **Expert Execution (Sparse)**:
   - Instead of matrix multiplying `x` by one massive FFN, `x` is gathered and scattered to the specific expert FFNs.
   - For a given token, `output = Weight_1 * Expert_A(token) + Weight_2 * Expert_B(token)`.
   - The outputs are recombined. Shape returns to `(B, T, D)`.
5. **Output**: This allows the model to have $16 \times \text{FFN\_Size}$ total parameters, but only compute $2 \times \text{FFN\_Size}$ per forward pass.

## 7. Mathematical Foundations
While the exact architecture is secret, the GPT-4 paper made a massive contribution to the mathematics of **Predictable Scaling Laws**.

Training a 1.8 Trillion parameter model requires months of time on thousands of GPUs, costing tens of millions of dollars. If the hyper-parameters are slightly wrong, the run is ruined. OpenAI developed infrastructure to mathematically predict the final loss of the massive GPT-4 model by training models that were 10,000x smaller.
Let $L(C)$ be the final cross-entropy loss of a model trained with compute budget $C$. OpenAI found that the loss follows a precise power-law:
$$ L(C) = a C^{-b} + c $$
By training several tiny models with small compute budgets (e.g., $C_1, C_2, C_3$), fitting the constants $a, b, c$, and extrapolating the curve out 10,000x to the target compute budget of GPT-4, they accurately predicted GPT-4's final loss before the training run even began.
Furthermore, they predicted its performance on specific downstream metrics (like the HumanEval coding benchmark) using the same power-law extrapolation:
$$ \text{pass@1}(C) = \alpha - \exp(-\beta C^\gamma) $$
This mathematical predictability is the secret to modern AI labs; they no longer guess if a massive model will work. They calculate its intelligence beforehand.

## 8. Training Procedure
1. **Pre-Training (Compute)**: GPT-4 was trained on a Microsoft Azure supercomputer. Leaks suggest it utilized roughly 25,000 Nvidia A100 GPUs for 90 to 100 days.
2. **Alignment & Safety**: OpenAI spent 6 months *after* pre-training strictly on safety alignment. They hired "Red Teams" (domain experts in cybersecurity, bio-terrorism, and hate speech) to actively attack the model, discovering its failure modes.
3. **Rule-Based Reward Models (RBRMs)**: During the PPO phase of RLHF, humans cannot monitor every output. RBRMs are smaller AI models trained specifically to read a prompt and GPT-4's response, and output a massive negative reward penalty if the response contains instructions on how to build a weapon, write malware, or generate hate speech. This automated safety loop was critical to making GPT-4 safe for public API access.
4. **Post-Training Optimization**: To support the massive 128K context window in later iterations, they utilized FlashAttention and aggressively optimized KV-cache quantization to ensure the model could serve long contexts without exhausting GPU memory.

## 9. PyTorch Implementation
We cannot implement GPT-4, but we can implement a minimal version of the Sparse Mixture of Experts (MoE) router, which is the rumored core of GPT-4's massive capacity.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class Expert(nn.Module):
    def __init__(self, d_model: int):
        super().__init__()
        # Standard MLP
        self.net = nn.Sequential(
            nn.Linear(d_model, 4 * d_model),
            nn.GELU(),
            nn.Linear(4 * d_model, d_model)
        )
    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.net(x)

class MoELayer(nn.Module):
    def __init__(self, d_model: int, num_experts: int = 8, top_k: int = 2):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k
        
        # Router network to decide which experts to use
        self.router = nn.Linear(d_model, num_experts)
        
        # Instantiate the experts
        self.experts = nn.ModuleList([Expert(d_model) for _ in range(num_experts)])

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B, T, D = x.shape
        x_flat = x.view(-1, D) # (B*T, D)
        
        # Calculate routing probabilities
        router_logits = self.router(x_flat) # (B*T, E)
        routing_probs = F.softmax(router_logits, dim=-1)
        
        # Select top-k experts for each token
        topk_probs, topk_indices = torch.topk(routing_probs, self.top_k, dim=-1) # Both (B*T, K)
        
        # Normalize the probabilities of the selected experts so they sum to 1
        topk_probs = topk_probs / topk_probs.sum(dim=-1, keepdim=True)
        
        final_output = torch.zeros_like(x_flat)
        
        # In a real distributed setup, this is heavily parallelized.
        # For simplicity, we loop over experts.
        for i, expert in enumerate(self.experts):
            # Find which tokens chose this expert
            token_mask = (topk_indices == i) # (B*T, K)
            
            # If any tokens chose this expert
            if token_mask.any():
                # Get the indices of the tokens
                token_idx, k_idx = torch.where(token_mask)
                
                # Extract the tokens and pass through expert
                expert_input = x_flat[token_idx]
                expert_output = expert(expert_input)
                
                # Weight the output by the routing probability and add to final
                weights = topk_probs[token_idx, k_idx].unsqueeze(-1)
                final_output[token_idx] += expert_output * weights
                
        return final_output.view(B, T, D)

# --- Shape Verification Test ---
if __name__ == "__main__":
    BATCH_SIZE, SEQ_LEN = 2, 64
    D_MODEL = 512
    NUM_EXPERTS, TOP_K = 16, 2
    
    moe_layer = MoELayer(D_MODEL, NUM_EXPERTS, TOP_K)
    x = torch.randn(BATCH_SIZE, SEQ_LEN, D_MODEL)
    
    output = moe_layer(x)
    
    expected_shape = (BATCH_SIZE, SEQ_LEN, D_MODEL)
    assert output.shape == expected_shape, f"Shape mismatch! Expected {expected_shape}, got {output.shape}"
    print(f"Test passed! MoE Layer correctly routed tokens to {TOP_K} out of {NUM_EXPERTS} experts.")
```

## 10. Strengths
GPT-4's dominant strength is its unparalleled reasoning and logic capability. It established itself as the state-of-the-art across nearly every academic, professional, and programming benchmark upon release. It handles complex, multi-constraint instructions flawlessly, making it the premier choice for coding assistance and autonomous agents. Secondly, its native multimodality (vision) is seamlessly integrated. It doesn't just describe images; it can reason about them logically (e.g., explaining *why* a meme is funny, or calculating the physics of an object in a photo). Finally, its safety alignment is incredibly robust. The integration of Red Teaming and Rule-Based Reward Models resulted in a model that is highly resistant to standard jailbreaks, allowing enterprises to deploy GPT-4 into customer-facing applications with a high degree of confidence that it will not generate toxic or dangerous material.

## 11. Weaknesses
GPT-4 is slow and expensive. The massive parameter count (even with sparse MoE routing) results in high inference latency and high API costs compared to models like GPT-3.5 or open-source alternatives like Llama-3, making it overkill for simple tasks like summarization or classification. Furthermore, its extreme safety alignment often results in "refusal fatigue"—the model will frequently refuse benign requests because they trigger a false positive in the safety filter. Secondly, while hallucination is drastically reduced compared to GPT-3, it is not eliminated. GPT-4 will still confidently generate false citations or hallucinate APIs in code, which is particularly dangerous because its output is so logically sound and authoritative that humans are much less likely to double-check it. Finally, the complete lack of open-source weights or architectural details heavily restricts academic researchers from studying or improving the base model.

## 12. Research Evolution
GPT-4 represents the end of the "Open" in OpenAI, transitioning the company fully into a closed, product-driven enterprise. The decision to withhold all architectural and training details set a new, highly secretive standard for frontier AI labs (followed closely by Anthropic and Google). Scientifically, GPT-4 proved the validity of predictable scaling laws, showing that massive infrastructure investments carry low scientific risk because the final intelligence can be calculated accurately in advance. Following GPT-4, the research frontier shifted away from pure scale and toward efficiency. Competitors (and OpenAI themselves) realized that while 1.8 Trillion parameters is powerful, running it is a logistical nightmare. This led to the development of GPT-4o (a more unified, faster omni-model) and the massive push by open-source competitors (like Meta's Llama series) to reach GPT-4 level performance using drastically fewer parameters through better data curation and denser architectures.

## 13. Interview Questions
**Q1: Why did OpenAI release zero architectural details in the GPT-4 Technical Report?**
**A1:** OpenAI cited two main reasons: 1) The intense commercial competition in the AI space, treating the architecture and dataset as highly valuable trade secrets. 2) Safety concerns, arguing that releasing the blueprint for a highly capable, potentially dangerous model to the public was irresponsible. This was a massive shift from their open-science approach in the GPT-2/3 era.

**Q2: What is a Sparse Mixture of Experts (MoE), and why is GPT-4 widely believed to use it?**
**A2:** MoE replaces the single massive Feed-Forward Network in a transformer with several smaller "expert" networks. A router sends each token to only 1 or 2 experts. This allows the model to have a massive total parameter count (high capacity for knowledge) without requiring massive compute for every single token. Leaks suggest GPT-4 uses a 16-expert MoE to achieve its scale efficiently.

**Q3: How did OpenAI predict the final loss of GPT-4 before spending millions of dollars to train it?**
**A3:** They derived Predictable Scaling Laws. By training several models that were 1,000x to 10,000x smaller, they plotted the cross-entropy loss against the compute budget. Because the relationship follows a strict power-law, they mathematically extrapolated the curve out to the massive compute budget of GPT-4, predicting its final intelligence accurately.

**Q4: What is a Rule-Based Reward Model (RBRM) and how did it improve GPT-4's safety?**
**A4:** RBRMs are secondary AI models used during the RLHF process. Instead of relying solely on human labelers, RBRMs are trained to act as strict judges that evaluate GPT-4's outputs against a set of safety rules (e.g., "does this text contain hate speech?"). If it does, the RBRM applies a massive negative reward, automating the safety alignment process at scale.

**Q5: How does GPT-4's multimodality differ from using a separate Image-to-Text model?**
**A5:** Instead of using an external model to generate a text caption of an image and feeding that caption to the LLM, GPT-4 processes the visual features directly in the same latent space as the text. This allows the transformer attention heads to reason about the deep relationships between the visual data and the text prompt natively, enabling tasks like explaining visual jokes.
