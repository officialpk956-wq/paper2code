# LLaMA 3

## 1. Overview
LLaMA 3 represents a massive leap in the open-weights AI ecosystem, released by Meta in April 2024. Building heavily on the architectural foundation of LLaMA 2, LLaMA 3 shifts the focus entirely to scale and data quality. Released initially in 8B and 70B parameter sizes (with a massive 405B version following later), these models were trained on a staggering 15 Trillion tokens—seven times larger than LLaMA 2's dataset. This extreme "over-training" past the Chinchilla optimal point resulted in an 8B model that rivaled or outperformed the previous generation's 70B model, and a 70B model that competed closely with frontier closed models like GPT-4. Architecturally, LLaMA 3 transitioned to a new tokenizer with a 128K vocabulary size, drastically improving multilingual and coding efficiency. Furthermore, it adopted Grouped-Query Attention (GQA) across all model sizes (not just the largest), standardizing high-efficiency inference. LLaMA 3 set a new, significantly higher bar for open-source AI capabilities across reasoning, code generation, and instruction following.

:::tip
LLaMA 3 8B is a prime example of "inference-optimal" scaling. By spending massive amounts of compute during pre-training (15T tokens), Meta created a small model that is incredibly smart but very cheap for end-users to run locally on consumer hardware.
:::

## 2. Historical Context
By early 2024, the AI landscape was fiercely competitive. While LLaMA 2 was the open-source standard, closed models like GPT-4, Claude 3, and Gemini 1.5 were significantly further ahead in reasoning and context length. Meanwhile, smaller open models from Mistral (like Mistral 7B) had proven that LLaMA 2 7B/13B were highly inefficient. Meta needed a response that reclaimed the open-source crown. LLaMA 3 was the answer, heavily focused on the lesson the industry learned post-Chinchilla: data is everything. Meta constructed massive new GPU clusters (totaling hundreds of thousands of H100s) to train LLaMA 3 on an unprecedented 15 Trillion tokens. The release was strategically phased, offering the highly efficient 8B and 70B models first to capture developers, while training the 405B behemoth to eventually challenge the frontier closed models directly.

## 3. Problem It Solves
LLaMA 3 tackles the performance plateau of open-source models and the inefficiency of language encoding. Firstly, LLaMA 2 struggled significantly with complex reasoning, mathematics, and advanced coding tasks compared to GPT-4. LLaMA 3 solves this by expanding the training data to 15T tokens with a massive focus on high-quality code and math data, resulting in a dramatic step-function improvement in these areas. Secondly, LLaMA 2's tokenizer (32K vocabulary) was highly inefficient for non-English languages, often requiring multiple tokens to encode a single foreign character. LLaMA 3 solves this by adopting a customized Tiktoken-based tokenizer with a 128K vocabulary, allowing it to compress multilingual text and code much more efficiently, effectively giving the model a longer effective context window and better non-English performance. Finally, by standardizing GQA on the 8B model, it solves memory bottleneck issues for local edge deployment.

## 5. Layer-by-Layer Breakdown
The structural DNA of LLaMA 3 mirrors LLaMA 2, operating as a dense, decoder-only Transformer. The sequence initiates at the **Token Embedding**, which is significantly wider than before due to the expanded 128,000 token vocabulary.

Within the **Transformer Blocks**, the data undergoes pre-normalization via **RMSNorm**. The most notable architectural standardization is the use of **Grouped-Query Attention (GQA)** across all model variants, including the small 8B model. In LLaMA 2, only the 70B model used GQA. By bringing GQA to the 8B size, Meta ensured that the smaller model remains highly memory efficient during inference, minimizing KV cache size. **Rotary Position Embeddings (RoPE)** are used for spatial awareness. The base RoPE frequency was likely adjusted to natively support the much larger context windows (initially 8K, later extended to 128K tokens).

The network utilizes the **SwiGLU** activation in its Feed-Forward Network. After propagating through the blocks, a **Final RMSNorm** prepares the tensor for the **Linear Output Head**, which maps the hidden states back to the massive 128K vocabulary space to generate predictions.

## 6. Tensor Flow Walkthrough
Let's examine the tensor flow for the LLaMA 3 8B model, focusing on the GQA dimensions. Assume Batch `B=4`, Sequence `T=8192`, `D_model=4096`, Query Heads `H_q=32`, KV Heads `H_kv=8`.

1.  **Input to Block:** `X`
    *   Shape: `(B, T, D_model)` -> `(4, 8192, 4096)`
2.  **RMSNorm 1:** `X_norm = RMSNorm(X)`
    *   Shape: `(B, T, D_model)` -> `(4, 8192, 4096)`
3.  **GQA Projections:**
    *   `D_head = D_model / H_q = 128`
    *   `Q` projection: `(B, T, H_q, D_head)` -> `(4, 8192, 32, 128)`
    *   `K, V` projections: `(B, T, H_kv, D_head)` -> `(4, 8192, 8, 128)`
4.  **Attention Calculation:**
    *   Each of the 8 KV heads is shared by 4 Query heads.
    *   `Attn = Softmax(Q * K^T) * V`
    *   Output before projection: `(B, T, H_q, D_head)` -> `(4, 8192, 32, 128)`
5.  **GQA Output Projection:**
    *   `Attn_out` Shape: `(B, T, D_model)` -> `(4, 8192, 4096)`
6.  **Residual Add 1:** `X = X + Attn_out`
    *   Shape: `(B, T, D_model)` -> `(4, 8192, 4096)`
7.  **SwiGLU FFN:**
    *   `D_ff` is scaled up (e.g., ~14336).
    *   `FFN_out` Shape: `(B, T, D_model)` -> `(4, 8192, 4096)`
8.  **Residual Add 2:** `X_out = X + FFN_out`
    *   Shape: `(B, T, D_model)` -> `(4, 8192, 4096)`
9.  **Final Output Head (Vocabulary):**
    *   `Vocab_size = 128256`
    *   Logits Shape: `(B, T, Vocab_size)` -> `(4, 8192, 128256)`

## 7. Mathematical Foundations
While the core architecture is unchanged, the mathematical foundation of LLaMA 3's success lies in the scaling laws and the tokenization efficiency.

**1. Inference-Optimal Scaling:**
Chinchilla dictates $N_{opt} \approx D_{opt}$ (scaling parameters and data equally). For an 8B model, the Chinchilla optimal training data is $\approx 160$ Billion tokens. LLaMA 3 8B was trained on **15 Trillion** tokens. This massive over-training pushes the loss curve down significantly further for a fixed parameter size. The math is purely economic: spending millions of dollars extra on pre-training FLOPs allows you to serve a much smarter 8B model for pennies during inference, compared to serving a strictly compute-optimal 70B model.

**2. Tokenizer Compression:**
LLaMA 2 used a 32K vocabulary. LLaMA 3 uses a 128K vocabulary. A larger vocabulary means that common sequences of characters, especially in code or non-English languages, can be represented by a single token instead of split across multiple tokens. 
Let $S$ be a string of text. Let $N_{32k}(S)$ be the number of tokens required to encode $S$ with LLaMA 2, and $N_{128k}(S)$ for LLaMA 3. 
Empirically, $N_{128k}(S) < N_{32k}(S)$, often by 15-20%.
Because transformer compute scales as $O(N^2)$ with sequence length, this compression acts as a mathematical speedup and effectively increases the model's context window. It can process more actual text within the same 8K token limit.

## 8. Training Procedure
LLaMA 3's training procedure was defined by massive scale and rigorous data curation.

**Data Filtering:** The 15 Trillion token dataset was heavily filtered. Meta used heuristic filters, NSFW filters, semantic deduplication, and importantly, used earlier versions of LLaMA to filter the training data for LLaMA 3, ensuring high quality. They intentionally over-sampled code and mathematical data to boost reasoning capabilities.

**Training Scale:** The models were trained on clusters containing up to 24,000 H100 GPUs. Training at this scale requires immense orchestration to handle hardware failures, utilizing advanced 4D parallelization (tensor, pipeline, context, and data parallelism).

**Post-Training (Alignment):** The instruction-tuned models underwent a highly refined RLHF pipeline. They used a combination of Supervised Fine-Tuning (SFT), Rejection Sampling, and Proximal Policy Optimization (PPO), alongside Direct Preference Optimization (DPO). The quality of the SFT prompts and preference data was significantly higher than LLaMA 2, leading to much better instruction following and a dramatic reduction in the "false refusal" rate (where the model incorrectly refuses a benign prompt for safety reasons).

## 9. PyTorch Implementation
Because LLaMA 3's architecture is so similar to LLaMA 2, this implementation focuses on standardizing Grouped-Query Attention, which is now present across all LLaMA 3 sizes.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class LLaMA3_Attention(nn.Module):
    def __init__(self, d_model, n_heads, n_kv_heads):
        super().__init__()
        # In LLaMA 3 8B, d_model=4096, n_heads=32, n_kv_heads=8
        self.n_heads = n_heads
        self.n_kv_heads = n_kv_heads
        self.head_dim = d_model // n_heads
        self.n_rep = n_heads // n_kv_heads
        
        self.wq = nn.Linear(d_model, n_heads * self.head_dim, bias=False)
        self.wk = nn.Linear(d_model, n_kv_heads * self.head_dim, bias=False)
        self.wv = nn.Linear(d_model, n_kv_heads * self.head_dim, bias=False)
        self.wo = nn.Linear(n_heads * self.head_dim, d_model, bias=False)

    def forward(self, x):
        B, T, _ = x.shape
        
        # Projections
        xq = self.wq(x).view(B, T, self.n_heads, self.head_dim)
        xk = self.wk(x).view(B, T, self.n_kv_heads, self.head_dim)
        xv = self.wv(x).view(B, T, self.n_kv_heads, self.head_dim)
        
        # Transpose for attention
        xq = xq.transpose(1, 2) # (B, n_heads, T, head_dim)
        xk = xk.transpose(1, 2) # (B, n_kv_heads, T, head_dim)
        xv = xv.transpose(1, 2) # (B, n_kv_heads, T, head_dim)
        
        # Expand KV heads to match Query heads (GQA)
        xk = torch.repeat_interleave(xk, self.n_rep, dim=1)
        xv = torch.repeat_interleave(xv, self.n_rep, dim=1)
        
        # Attention calculation (simplified, no RoPE/mask for brevity)
        scores = torch.matmul(xq, xk.transpose(-2, -1)) / (self.head_dim ** 0.5)
        attn = F.softmax(scores, dim=-1)
        out = torch.matmul(attn, xv)
        
        # Recombine heads
        out = out.transpose(1, 2).contiguous().view(B, T, -1)
        return self.wo(out)

# --- Test ---
if __name__ == "__main__":
    B, T, d_model = 2, 64, 4096
    n_heads, n_kv_heads = 32, 8 # LLaMA 3 8B configuration
    
    attn = LLaMA3_Attention(d_model, n_heads, n_kv_heads)
    x = torch.randn(B, T, d_model)
    out = attn(x)
    
    print(f"Input shape: {x.shape}")
    print(f"Output shape: {out.shape}")
    assert out.shape == (B, T, d_model), "Shape mismatch!"
    print(f"Test passed: Universal GQA evaluated successfully for config {n_heads}Q/{n_kv_heads}KV.")
```

## 10. Strengths
LLaMA 3's overwhelming strength is its performance-to-size ratio, driven by extreme data scaling. The 8B model represents a sweet spot for local deployment; it is small enough to run on consumer laptops (like MacBooks) or edge devices, yet it possesses the reasoning and coding capabilities of much larger enterprise models from a year prior. The 70B and 405B models provide frontier-level capabilities matching or exceeding GPT-4 in many benchmarks. The new 128K tokenizer is a massive strength, drastically improving performance in non-English languages and making it far more efficient for coding tasks. Finally, the post-training alignment is significantly improved; LLaMA 3 models are much less prone to the "refusal" issues that plagued LLaMA 2, making them much more helpful assistants.

## 11. Weaknesses
One notable weakness of the initial LLaMA 3 release was the context window, which was limited to 8K tokens. In an era where competitors offered 128K to 1M token contexts natively, 8K was severely restrictive for tasks like document QA or codebase analysis (though Meta later released versions supporting 128K). Additionally, the expanded 128K vocabulary size means the embedding matrix and the final output head contain significantly more parameters. For the small 8B model, a massive percentage of its parameters (over 1B) are tied up solely in the embeddings rather than the reasoning transformer blocks, which can be seen as parametrically inefficient for a small model.

## 12. Research Evolution
LLaMA 3 is the culmination of the "data is king" philosophy. The original LLaMA proved small models work. LLaMA 2 proved open models can be safe. LLaMA 3 proved that you can push a small architecture infinitely further simply by feeding it more, higher-quality data. It represents a shift away from discovering new model architectures (LLaMA 3 is architecturally almost identical to LLaMA 2) and towards perfecting the data pipeline and training infrastructure. The use of older LLMs to filter data for new LLMs highlights a new era of recursive self-improvement in AI training. Furthermore, the 405B parameter model signifies Meta's commitment to competing directly with closed-source frontier models, pushing the boundaries of what is available as open-weights.

## 13. Interview Questions

**Q1: What does it mean that LLaMA 3 8B is an "inference-optimal" model compared to a "compute-optimal" model?**
**A1:** A compute-optimal model (like Chinchilla) minimizes training loss for a fixed training budget by scaling parameters and data equally. However, LLaMA 3 8B was trained on 15 Trillion tokens—way past the compute-optimal point for 8B parameters. Meta spent excess money during pre-training to make the 8B model as smart as possible. This is "inference-optimal" because the end user gets a highly capable model that is very small, meaning it uses very little VRAM and compute to run in production, saving massive amounts of money over the model's deployed lifespan.

**Q2: Why did Meta upgrade the tokenizer vocabulary from 32K in LLaMA 2 to 128K in LLaMA 3, and what is the trade-off?**
**A2:** A larger vocabulary (128K) allows the tokenizer to compress text more efficiently. Instead of breaking a complex foreign word or a snippet of code into 4 or 5 tokens, it might encode it in 1 or 2 tokens. This effectively increases the context window (you can fit more actual text into 8192 tokens) and speeds up generation. The trade-off is model size: the embedding matrix and the final output layer scale with the vocabulary size. In the 8B model, this adds hundreds of millions of parameters that are just lookup tables, taking away parameter budget from the deep reasoning layers.

**Q3: How does the universal adoption of Grouped-Query Attention (GQA) in LLaMA 3 8B benefit local developers?**
**A3:** In LLaMA 2, only the 70B model had GQA; the 7B used standard Multi-Head Attention (MHA). MHA requires a large amount of memory to store the Key-Value (KV) cache for previous tokens during generation. By using GQA in the 8B model, LLaMA 3 drastically reduces the size of the KV cache. This means a developer running LLaMA 3 8B on a consumer GPU can run much larger batch sizes or process much longer context lengths before running out of VRAM, compared to an MHA model of the same size.

**Q4: LLaMA 3 initially launched with an 8K context window, while competitors had 128K+. Why is training for long context difficult?**
**A4:** The primary difficulty is the quadratic scaling of standard attention: compute and memory scale as $O(N^2)$ with sequence length. Training on 128K sequences requires massive amounts of GPU memory and specialized techniques like Ring Attention to distribute the sequence across multiple GPUs. Furthermore, if you simply increase the context length without carefully curating long-context training data (like whole books or codebases), the model struggles to actually retrieve information from the middle of the context window (the "lost in the middle" phenomenon).

**Q5: What role did Direct Preference Optimization (DPO) play in LLaMA 3's alignment compared to LLaMA 2?**
**A5:** LLaMA 2 primarily used PPO (Proximal Policy Optimization) for RLHF, which is complex, unstable, and requires training a separate reward model. DPO is a newer technique that allows for alignment directly from human preference data without needing a separate reward model. The loss function in DPO directly increases the probability of the preferred response and decreases the probability of the rejected one. Meta used DPO alongside other techniques in LLaMA 3 to create a more robust, stable, and less overly-cautious instruction-following model.
