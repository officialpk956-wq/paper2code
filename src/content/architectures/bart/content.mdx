# BART

## 1. Overview
BART (Bidirectional and Auto-Regressive Transformers), introduced by Mike Lewis and researchers at Facebook AI (FAIR) in 2019, represents a fundamental architectural synthesis in the evolution of Large Language Models. While BERT proved that bidirectional encoders excel at understanding text (NLU), and GPT proved that autoregressive decoders excel at generating text (NLG), BART seamlessly combines both into a standard sequence-to-sequence (seq2seq) Transformer. Its primary innovation is its pre-training objective: it acts as a Denoising Autoencoder. During pre-training, input text is intentionally corrupted in wildly destructive ways—tokens are masked, deleted, permuted, rotated, and chunks are replaced with single masks. The corrupted text is passed through the bidirectional encoder. The autoregressive decoder is then tasked with perfectly reconstructing the original, uncorrupted text. This rigorous pre-training forces BART to learn deep semantics and syntax, making it extraordinarily powerful for generative tasks like text summarization, machine translation, and generative question answering, while still maintaining BERT-like performance on comprehension tasks.

:::tip
If your task requires generating text based on a specific input document (e.g., summarizing an article, translating a sentence, or rewriting a paragraph), BART (or its Google equivalent, T5) should be your default starting architecture over encoder-only models like BERT.
:::

## 2. Historical Context
By late 2019, the NLP field had branched into two distinct paradigms based on the original Transformer architecture. Google's BERT utilized only the Encoder half, utilizing Masked Language Modeling (MLM) to achieve state-of-the-art results on discriminative tasks (classification, QA). OpenAI's GPT utilized only the Decoder half, predicting the next word to achieve incredible results on open-ended generation. However, researchers recognized a gap: how do we build models that excel at *conditional* generation (generating text conditioned on a specific input)? Models like BERT couldn't generate text autoregressively, and models like GPT only read text left-to-right, meaning they lacked deep bidirectional context of the input prompt. The authors of BART returned to the original 2017 Transformer paper (which was a seq2seq model designed for translation) and applied modern self-supervised pre-training to it. By generalizing BERT's masking concept into full-scale document corruption, BART proved that a unified architecture could achieve the best of both worlds, heavily influencing the future development of encoder-decoder LLMs like T5.

## 3. Problem It Solves
BART solves the problem of conditional text generation that pure encoders (BERT) and pure decoders (GPT) struggle with. Consider text summarization. You need to read an entire article, understand the complex bidirectional relationships between all the paragraphs, and then write a concise summary one word at a time. A BERT model can read the article perfectly but cannot write the summary. A GPT model can write the summary beautifully but reads the article blindly from left to right, missing crucial forward context early on. BART solves this by using a Bidirectional Encoder to read the input article. It analyzes the entire document simultaneously, exactly like BERT. The output of this encoder is then passed to an Autoregressive Decoder via Cross-Attention. The decoder uses this deep understanding to generate the summary one word at a time, exactly like GPT. By pre-training this entire system to reconstruct heavily corrupted documents (e.g., restoring deleted words and un-permuting sentences), BART learns a robust internal representation of language structure that translates perfectly to tasks like summarization and translation.

## 4. Architecture Diagram Data
```text
                   [ Target Output Text ]
                  "The cat sat on the mat."
                             ^
                             | (Next Token Prediction)
             +---------------+---------------+
             |       Autoregressive Decoder  |
             |  (Masked Self-Attention +     |
             |   Cross-Attention)            |
             +---------------+---------------+
                             ^
                             |  [ Cross Attention ]
             +---------------+---------------+
             |       Bidirectional Encoder   |
             |      (Full Self-Attention)    |
             +---------------+---------------+
                             ^
                             |
                   [ Corrupted Input ]
                 "cat The on [MASK] mat."  (Permuted & Masked)
```
**Components:**
- `Corrupted Input`: The original text subjected to noise (Token Masking, Token Deletion, Text Infilling, Sentence Permutation, Document Rotation).
- `Bidirectional Encoder`: A BERT-like stack of Transformer encoder layers. Every token attends to every other token. It processes the corrupted input and outputs contextualized hidden states.
- `Cross Attention`: The decoder layers attend to the final hidden states of the encoder, allowing the generation process to condition on the input document.
- `Autoregressive Decoder`: A GPT-like stack of Transformer decoder layers. It uses causal (masked) self-attention, meaning token $t$ can only attend to tokens $\le t$. It predicts the original uncorrupted text one token at a time.

## 5. Layer-by-Layer Breakdown
Structurally, BART is almost identical to the original Vaswani et al. (2017) Transformer.
1. **Input Corruption**: During pre-training, text is corrupted. Unlike BERT which only replaces tokens with `[MASK]`, BART uses Text Infilling (replacing spans of text with a single mask token to teach the model to predict how many words are missing), Token Deletion (forcing the model to find missing positions), and Sentence Permutation.
2. **Encoder Input Processing**: The corrupted token IDs are passed through an embedding layer (Token + Absolute Position embeddings).
3. **Encoder Blocks**: The embeddings pass through $N$ encoder layers (6 for Base, 12 for Large). Each layer performs unmasked Multi-Head Self-Attention followed by a Feed-Forward Network. The output is a sequence of hidden vectors representing the corrupted text.
4. **Decoder Input Processing**: The input to the decoder is the *uncorrupted* text, shifted right by one position (starting with a `<s>` token).
5. **Decoder Blocks**: The data passes through $N$ decoder layers. Each layer performs:
   - **Masked Self-Attention**: Ensures the model can only look at past generated words.
   - **Encoder-Decoder Cross-Attention**: The queries come from the decoder's self-attention, while the Keys and Values come from the Encoder's final output. This is how the decoder "reads" the encoded document.
   - **Feed-Forward Network**.
6. **Output Head**: A linear layer and softmax over the vocabulary predict the next token in the uncorrupted sequence.

:::warning
Because it contains both an encoder and a decoder, a BART model with 12 encoder layers and 12 decoder layers actually has roughly double the parameter count of a 12-layer BERT model, making inference heavier.
:::

## 6. Tensor Flow Walkthrough
Let's trace the shapes for a forward pass during pre-training.
- `B`: Batch size
- `T_enc`: Encoder sequence length (corrupted input)
- `T_dec`: Decoder sequence length (target output)
- `D`: Hidden dimension (768 for Base)

1. **Encoder Input (`x_enc`)**: Shape `(B, T_enc)`. Corrupted text.
2. **Encoder Execution**:
   - `enc_hidden = Encoder(x_enc)`: Shape `(B, T_enc, D)`.
3. **Decoder Input (`x_dec`)**: Shape `(B, T_dec)`. Uncorrupted text shifted right.
4. **Decoder Execution**:
   - `dec_embeds = Embedding(x_dec)`: Shape `(B, T_dec, D)`.
   - **Masked Self-Attention**: Operates on `dec_embeds`. Output `(B, T_dec, D)`.
   - **Cross-Attention**:
     - Query: from Decoder, `(B, T_dec, D)`.
     - Key/Value: `enc_hidden` from Encoder, `(B, T_enc, D)`.
     - Output `(B, T_dec, D)`.
   - `dec_hidden = DecoderBlock(dec_embeds, enc_hidden)`: Shape `(B, T_dec, D)`.
5. **Output Projection**:
   - `logits = Linear(dec_hidden)`: Shape `(B, T_dec, V)`.
6. **Loss**: Cross-entropy between `logits` and the actual uncorrupted target text.

## 7. Mathematical Foundations
The foundation of BART is the standard seq2seq objective combined with denoising.

**Seq2Seq Objective:**
Given an input sequence $X$ (corrupted) and a target sequence $Y$ (uncorrupted) of length $N$, the autoregressive decoder models the conditional probability:
$$ P(Y | X) = \prod_{i=1}^N P(y_i | y_{<i}, X) $$
The model is trained to minimize the negative log-likelihood:
$$ \mathcal{L}_{BART} = - \sum_{i=1}^N \log P(y_i | y_{<i}, X; \theta) $$
where $\theta$ represents the parameters of both the encoder and decoder.

**Cross-Attention Mechanism:**
In the decoder layer, let $H_{dec}$ be the hidden state from the masked self-attention sublayer, and $H_{enc}$ be the final hidden state of the encoder. The cross-attention calculates:
$$ Q = H_{dec} W_Q $$
$$ K = H_{enc} W_K $$
$$ V = H_{enc} W_V $$
$$ \text{CrossAttn}(Q, K, V) = \text{softmax}\left(\frac{Q K^\top}{\sqrt{d_k}}\right) V $$
This mechanism allows the probability of the *next* token $y_i$ being generated by the decoder to be directly influenced by the encoder's bidirectional understanding of the corrupted input $X$.

## 8. Training Procedure
1. **Document Corruption Function**: BART's genius lies in its corruption strategy. It applies multiple noise functions simultaneously:
   - **Token Masking**: 15% of tokens replaced by `[MASK]`.
   - **Token Deletion**: Random tokens are deleted entirely (forcing the model to predict missing positions, unlike masking where the position is known).
   - **Text Infilling**: Spans of text (length drawn from a Poisson distribution) are replaced by a *single* `[MASK]` token. E.g., "The cat sat on the mat" -> "The [MASK] the mat". This forces the model to predict how many tokens are missing.
   - **Sentence Permutation**: A document is divided into sentences, and their order is randomly shuffled.
   - **Document Rotation**: A random token is chosen, and the document is rotated so that token is the start, forcing the model to identify the logical beginning.
2. **Forward/Backward Pass**: The corrupted document passes through the encoder. The decoder uses teacher forcing to predict the uncorrupted document. Gradients update both encoder and decoder simultaneously via the cross-entropy loss.
3. **Fine-tuning**: For sequence generation (summarization), the input goes to the encoder, and the decoder generates text autoregressively. For classification, the input goes to both encoder and decoder, and the representation of the final decoder token is used for classification (acting like a BERT `[CLS]` token).

## 9. PyTorch Implementation
Here is a conceptual implementation of the BART architecture, focusing on the connection between the Bidirectional Encoder and the Autoregressive Decoder via cross-attention.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class BARTSeq2Seq(nn.Module):
    def __init__(self, vocab_size: int, d_model: int, n_heads: int, num_encoder_layers: int, num_decoder_layers: int):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, d_model)
        
        # 1. Bidirectional Encoder (No causal mask)
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=n_heads, batch_first=True
        )
        self.encoder = nn.TransformerEncoder(encoder_layer, num_layers=num_encoder_layers)
        
        # 2. Autoregressive Decoder (Uses causal mask and cross-attention)
        decoder_layer = nn.TransformerDecoderLayer(
            d_model=d_model, nhead=n_heads, batch_first=True
        )
        self.decoder = nn.TransformerDecoder(decoder_layer, num_layers=num_decoder_layers)
        
        # 3. Output Head
        self.lm_head = nn.Linear(d_model, vocab_size, bias=False)
        # Weight tying (optional but common)
        self.lm_head.weight = self.embedding.weight

    def generate_square_subsequent_mask(self, sz: int) -> torch.Tensor:
        # Prevents decoder from looking at future tokens
        mask = (torch.triu(torch.ones(sz, sz)) == 1).transpose(0, 1)
        mask = mask.float().masked_fill(mask == 0, float('-inf')).masked_fill(mask == 1, float(0.0))
        return mask

    def forward(self, src_ids: torch.Tensor, tgt_ids: torch.Tensor) -> torch.Tensor:
        # src_ids: (B, T_enc) - The corrupted input
        # tgt_ids: (B, T_dec) - The target uncorrupted output (shifted right)
        
        # Embeddings
        src_emb = self.embedding(src_ids) # (B, T_enc, D)
        tgt_emb = self.embedding(tgt_ids) # (B, T_dec, D)
        
        # Encoder Pass (Bidirectional)
        memory = self.encoder(src_emb)    # (B, T_enc, D)
        
        # Decoder Pass (Autoregressive via Causal Mask)
        tgt_seq_len = tgt_ids.size(1)
        tgt_mask = self.generate_square_subsequent_mask(tgt_seq_len).to(tgt_ids.device)
        
        # The decoder takes target embeddings AND the encoder's memory
        output = self.decoder(tgt=tgt_emb, memory=memory, tgt_mask=tgt_mask) # (B, T_dec, D)
        
        # Project to vocabulary
        logits = self.lm_head(output)     # (B, T_dec, V)
        return logits

# --- Shape Verification Test ---
if __name__ == "__main__":
    BATCH_SIZE, T_ENC, T_DEC = 2, 20, 15
    VOCAB_SIZE, D_MODEL, N_HEADS = 10000, 512, 8
    
    model = BARTSeq2Seq(VOCAB_SIZE, D_MODEL, N_HEADS, num_encoder_layers=6, num_decoder_layers=6)
    
    # Dummy corrupted input and target shifted output
    src = torch.randint(0, VOCAB_SIZE, (BATCH_SIZE, T_ENC))
    tgt = torch.randint(0, VOCAB_SIZE, (BATCH_SIZE, T_DEC))
    
    logits = model(src, tgt)
    
    expected_shape = (BATCH_SIZE, T_DEC, VOCAB_SIZE)
    assert logits.shape == expected_shape, f"Shape mismatch! Expected {expected_shape}, got {logits.shape}"
    print("Test passed! Seq2Seq forward pass shapes are correct.")
```

## 10. Strengths
BART's ultimate strength is its versatility. Because it is a unified encoder-decoder model, it can be fine-tuned for virtually any NLP task. It excels spectacularly at text generation tasks where the output relies heavily on understanding a long input text, such as abstractive summarization, machine translation, and generating answers to complex questions based on provided context. The text infilling and token deletion corruption strategies force the model to learn how to manipulate the length of sequences (unlike BERT, which always replaces 1 token with 1 mask). This makes BART incredibly robust at tasks that require condensing long paragraphs into short sentences. Furthermore, despite being optimized for generation, BART maintains performance parity with RoBERTa on discriminative NLU tasks (like GLUE), meaning a single architecture can serve both generation and classification microservices effectively.

## 11. Weaknesses
The primary weakness of BART is its parameter footprint and latency compared to encoder-only models. A BART-base model contains 6 encoder layers and 6 decoder layers. During a classification task, the input must be processed by the encoder, and then the decoder must also run to generate the output state. This means BART is roughly twice as slow and takes twice as much memory as a BERT-base model for simple classification tasks. Furthermore, autoregressive generation is inherently slow because the decoder must be run in a loop, generating one token at a time; you cannot parallelize the output generation. Finally, while BART is excellent at conditional generation (summarization), it is generally outperformed by pure decoder models (like GPT-3) at completely open-ended generation (writing a story from a small prompt) because its architecture is heavily biased toward attending to an encoder memory state.

## 12. Research Evolution
BART represented the culmination of efforts to unify the divergent paths of BERT (encoders) and GPT (decoders). It proved that the original Vaswani Transformer architecture, when paired with modern, destructive self-supervised denoising objectives, was the optimal topology for seq2seq tasks. Contemporaneously, Google released T5 (Text-to-Text Transfer Transformer), which utilized a nearly identical encoder-decoder architecture and denoising objective, but framed every single NLP task (even classification) as a text generation problem. The success of BART and T5 cemented the encoder-decoder architecture as the absolute gold standard for summarization and translation for years. However, as the industry moved towards massive scale (100B+ parameters), the computational overhead of maintaining a separate encoder became prohibitive. The field largely shifted back to pure, massive autoregressive decoders (like GPT-4 and Llama), which proved capable of performing summarization without an encoder simply through massive scale and in-context learning.

## 13. Interview Questions
**Q1: How does BART's architecture differ fundamentally from BERT?**
**A1:** BERT is an encoder-only model designed to understand text. It cannot generate text easily. BART is an encoder-decoder (seq2seq) model. It uses a BERT-like bidirectional encoder to read the input, and a GPT-like autoregressive decoder to generate the output one token at a time, making it ideal for tasks like summarization.

**Q2: What is "Text Infilling" in BART's pre-training, and why is it important?**
**A2:** Text Infilling involves taking a span of words (e.g., 3 words) in the original text and replacing the entire span with a *single* `[MASK]` token. The model is forced to predict not just what words are missing, but how many. This teaches the model to flexibly alter sequence lengths, a critical skill for abstractive summarization.

**Q3: Explain the role of Cross-Attention in the BART architecture.**
**A3:** Cross-Attention bridges the encoder and decoder. In the decoder layers, the Self-Attention mechanism only looks at the words generated so far. The Cross-Attention mechanism takes the queries from the decoder and the Keys/Values from the final hidden state of the encoder. This is how the decoder "reads" the input document to inform what word it should generate next.

**Q4: Can BART be used for simple classification tasks like sentiment analysis? If so, how?**
**A4:** Yes. The input text is fed into the encoder, and the exact same text is fed into the decoder. The hidden state of the final token generated by the decoder (acting similarly to the `[CLS]` token in BERT) is extracted and passed through a linear classifier. It performs comparably to RoBERTa.

**Q5: Why might you choose RoBERTa over BART for a massive Named Entity Recognition (NER) pipeline?**
**A5:** Latency and compute efficiency. NER is a token-level classification task. RoBERTa (an encoder-only model) passes the text through its layers once and outputs the classifications. BART (encoder-decoder) must pass the text through the encoder, and then through the decoder layers. It does unnecessary extra work for non-generative tasks, making it slower and more expensive to run at scale.

## 14. Related Papers
- **BART: Denoising Sequence-to-Sequence Pre-training for Natural Language Generation, Translation, and Comprehension (Lewis et al., 2019)**: The foundational paper introducing the architecture and corruption schemes.
- **Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer (Raffel et al., 2019)**: The T5 paper from Google, released around the same time, which uses a very similar architecture and denoising objective.
