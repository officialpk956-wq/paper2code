# EfficientDet

## 1. Overview
EfficientDet, introduced in 2019 by Mingxing Tan, Ruoming Pang, and Quoc V. Le (Google Research, Brain Team), set a new paradigm for scalable, highly efficient object detection. Prior to EfficientDet, achieving high detection accuracy meant accepting massive model sizes and high computational costs (FLOPs). The Google team identified two major bottlenecks in existing architectures:
1. **Inefficient Multi-Scale Feature Fusion:** Traditional feature pyramids (FPN, PANet, NAS-FPN) either processed features unidirectionally or treated all input features equally regardless of their resolution. EfficientDet introduced **BiFPN (Bidirectional Feature Pyramid Network)**—a weighted, bidirectional feature pyramid that enables fast, multi-scale feature fusion while applying trainable scalar weights to let the network learn the importance of each resolution level.
2. **Uncoordinated Scaling:** Previous models scaled backbones, feature networks, or resolution independently. EfficientDet introduced **Compound Scaling**, scaling backbone depth/width, BiFPN layers, detection head layers, and input image resolution simultaneously using a single compound coefficient $\phi$.

:::note
EfficientDet-D7 achieved state-of-the-art 55.1 AP on MS COCO while being $9\times$ smaller (52M parameters) and running with $13\times$ fewer FLOPs than previous state-of-the-art detectors.
:::

## 2. Historical Context
By 2019, object detection models had grown exceedingly large. Architectures like NAS-FPN used neural architecture search to find complex feature pyramids, but the resulting networks were difficult to implement, memory-heavy, and unscalable. Furthermore, detectors were built by plugging a pre-trained classification backbone (e.g., ResNet) into an ad-hoc feature pyramid (e.g., FPN) with an arbitrary head, without any unified scaling law.

Tan and Le had previously published EfficientNet (2019), which revolutionized image classification by proving that scaling network depth, width, and resolution together using a fixed compound ratio outperformed scaling any single dimension in isolation. They brought this exact philosophy to object detection with EfficientDet. By pairing EfficientNet backbones with the novel BiFPN module and extending compound scaling across the entire detection pipeline (Backbone + BiFPN + Head + Resolution), EfficientDet established a family of models (D0 to D7x) that dominated efficiency leaderboards.

## 3. Problem It Solves
EfficientDet resolves three key design flaws in modern object detectors:
1. **Inefficient Feature Fusion in FPN/PANet:** FPN only propagates information top-down; PANet adds a bottom-up path but doubles nodes and parameters. BiFPN removes nodes with only one input edge (which contribute little) and adds residual shortcuts between input and output nodes at the same level, maximizing feature reuse at minimal cost.
2. **Equal Weighting of Unequal Features:** Traditional feature pyramids sum feature maps element-wise without considering that different resolutions contribute unequally to the output. BiFPN introduces **Fast Normalized Fusion**, learning a positive scalar weight for each input branch.
3. **Manual, Disjoint Model Resizing:** Replaces trial-and-error manual scaling with a single compound coefficient $\phi$ that systematically scales all components of the detector together.

## 5. Layer-by-Layer Breakdown
EfficientDet consists of three compound-scaled modules:

**1. EfficientNet Backbone:**
- Uses MBConv (Mobile Inverted Bottleneck Convolution) blocks with squeeze-and-excitation.
- Extracts features $\{P_3, P_4, P_5, P_6, P_7\}$ at strides $\{8, 16, 32, 64, 128\}$.

**2. BiFPN (Bidirectional Feature Pyramid Network):**
- **Node Pruning:** Removes single-input nodes that do not perform feature fusion.
- **Extra Residual Edge:** Adds a shortcut connection from the original input node to the output node at the same level if they reside at the same resolution.
- **Bidirectional Paths:** Combines top-down feature aggregation with bottom-up path aggregation in a single repeatable block.
- **Depthwise Separable Convolutions:** All feature fusion operations use Depthwise Separable Convs followed by Batch Normalization and SiLU activation.
- **Repetition:** The BiFPN block is repeated $N_{\text{bifpn}}$ times depending on the compound scaling coefficient $\phi$.

**3. Class and Box Prediction Heads:**
- Uses Depthwise Separable Convolutions to process multi-scale features from $P_3$ through $P_7$.
- Parameters are shared across all pyramid levels.
- Head depth (number of conv layers) and width (channels) scale continuously with $\phi$.

## 6. Tensor Flow Walkthrough
Let's trace tensors through EfficientDet-D0 for input `(B, 3, 512, 512)`, BiFPN channels $W_{\text{bifpn}} = 64$, $A=9$ anchors per cell, $K=90$ COCO classes.

1. **Backbone Feature Maps:**
   - $P_3$: `(B, 40, 64, 64)`   (Stride 8)
   - $P_4$: `(B, 112, 32, 32)`  (Stride 16)
   - $P_5$: `(B, 320, 16, 16)`  (Stride 32)
   - $P_6$: `(B, 64, 8, 8)`     (Conv 1x1 on $P_5$ + MaxPool)
   - $P_7$: `(B, 64, 4, 4)`     (MaxPool on $P_6$)

2. **Channel Projection to $W_{\text{bifpn}} = 64$:**
   - All levels projected to 64 channels: $P_3 \dots P_7 \rightarrow$ `(B, 64, H_i, W_i)`.

3. **BiFPN Layer Execution (Repeated $N_{\text{bifpn}} = 3$ times):**
   - Top-down + Bottom-up fusion with weighted scalars.
   - Outputs: $\{P_3^{\text{out}}, P_4^{\text{out}}, P_5^{\text{out}}, P_6^{\text{out}}, P_7^{\text{out}}\}$, each of shape `(B, 64, H_i, W_i)`.

4. **Prediction Heads ($D_{\text{head}} = 3$ layers):**
   - **Class Head:** 3x DepthwiseSeparableConv(64 $\rightarrow 64$) $\rightarrow$ Conv(64 $\rightarrow 9 \times 90 = 810$) $\rightarrow$ `(B, 810, H_i, W_i)`
   - **Box Head:** 3x DepthwiseSeparableConv(64 $\rightarrow 64$) $\rightarrow$ Conv(64 $\rightarrow 9 \times 4 = 36$) $\rightarrow$ `(B, 36, H_i, W_i)`

## 7. Mathematical Foundations

### 1. Fast Normalized Feature Fusion
Traditional feature fusion sums input tensors unweighted: $O = \sum_i I_i$.
Softmax-based weighting $O = \sum_i \frac{e^{w_i}}{\sum_j e^{w_j}} I_i$ is computationally slow on GPUs due to exponential functions.

EfficientDet introduces **Fast Normalized Fusion**, which guarantees non-negative weights using ReLU and achieves comparable accuracy at $1.5\times$ to $2\times$ faster speed:

$$O = \sum_{i} \frac{w_i}{\epsilon + \sum_{j} w_j} \cdot I_i$$

where $w_i \ge 0$ is ensured by applying ReLU after each learned scalar parameter $w_i$, and $\epsilon = 0.0001$ prevents division by zero.

For example, the intermediate top-down node $P_6^{\text{td}}$ and output node $P_6^{\text{out}}$ in BiFPN compute:

$$P_6^{\text{td}} = \text{Conv}\left( \frac{w_1 \cdot P_6^{\text{in}} + w_2 \cdot \text{Resize}(P_7^{\text{in}})}{w_1 + w_2 + \epsilon} \right)$$

$$P_6^{\text{out}} = \text{Conv}\left( \frac{w_1' \cdot P_6^{\text{in}} + w_2' \cdot P_6^{\text{td}} + w_3' \cdot \text{Resize}(P_5^{\text{out}})}{w_1' + w_2' + w_3' + \epsilon} \right)$$

### 2. Compound Scaling Coefficients ($\phi$)
All network dimensions scale as a function of a single user-defined integer coefficient $\phi \ge 0$:

1. **Input Resolution:** $R_{\text{image}} = 512 + \phi \cdot 128$
2. **BiFPN Width & Depth:** $W_{\text{bifpn}} = 64 \cdot (1.35^\phi), \quad D_{\text{bifpn}} = 3 + \phi$
3. **Head Depth:** $D_{\text{head}} = 3 + \lfloor \phi / 3 \rfloor$
4. **Backbone:** EfficientNet-B0 to B7 (scaled with $\phi$).

| Model | Compound $\phi$ | Input Res | BiFPN Channels ($W$) | BiFPN Layers ($D$) | Head Layers |
|---|---|---|---|---|---|
| **D0** | 0 | $512 \times 512$ | 64 | 3 | 3 |
| **D1** | 1 | $640 \times 640$ | 88 | 4 | 3 |
| **D2** | 2 | $768 \times 768$ | 112 | 5 | 3 |
| **D3** | 3 | $896 \times 896$ | 160 | 6 | 4 |
| **D7** | 7 | $1536 \times 1536$ | 384 | 8 | 5 |

## 8. Training Procedure
- **Focal Loss:** Uses Focal Loss ($\alpha = 0.25, \gamma = 1.5$) for classification and Smooth $L_1$ for box regression.
- **Optimizer:** SGD with momentum 0.9, weight decay $4 \times 10^{-5}$.
- **Learning Rate Schedule:** Cosine decay with linear warmup.
- **Data Augmentation:** AutoAugment / RandAugment with scale jittering ($0.1\times$ to $2.0\times$).

## 9. PyTorch Implementation
Here is a complete PyTorch implementation of the **BiFPN Layer with Fast Normalized Fusion**.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class DepthwiseSeparableConv(nn.Module):
    def __init__(self, in_ch, out_ch):
        super().__init__()
        self.depthwise = nn.Conv2d(in_ch, in_ch, kernel_size=3, padding=1, groups=in_ch, bias=False)
        self.pointwise = nn.Conv2d(in_ch, out_ch, kernel_size=1, bias=False)
        self.bn = nn.BatchNorm2d(out_ch)
        self.act = nn.SiLU(inplace=True)

    def forward(self, x):
        return self.act(self.bn(self.pointwise(self.depthwise(x))))

class BiFPNBlock(nn.Module):
    def __init__(self, num_channels=64, epsilon=1e-4):
        super().__init__()
        self.epsilon = epsilon
        
        # Convolutions for nodes
        self.conv6_td = DepthwiseSeparableConv(num_channels, num_channels)
        self.conv5_td = DepthwiseSeparableConv(num_channels, num_channels)
        self.conv4_td = DepthwiseSeparableConv(num_channels, num_channels)
        
        self.conv3_out = DepthwiseSeparableConv(num_channels, num_channels)
        self.conv4_out = DepthwiseSeparableConv(num_channels, num_channels)
        self.conv5_out = DepthwiseSeparableConv(num_channels, num_channels)
        self.conv6_out = DepthwiseSeparableConv(num_channels, num_channels)
        self.conv7_out = DepthwiseSeparableConv(num_channels, num_channels)
        
        # Learnable Fast Normalized Fusion Weights (initialized to 1.0)
        self.w_p6_td = nn.Parameter(torch.ones(2, dtype=torch.float32))
        self.w_p5_td = nn.Parameter(torch.ones(2, dtype=torch.float32))
        self.w_p4_td = nn.Parameter(torch.ones(2, dtype=torch.float32))
        
        self.w_p3_out = nn.Parameter(torch.ones(2, dtype=torch.float32))
        self.w_p4_out = nn.Parameter(torch.ones(3, dtype=torch.float32))
        self.w_p5_out = nn.Parameter(torch.ones(3, dtype=torch.float32))
        self.w_p6_out = nn.Parameter(torch.ones(3, dtype=torch.float32))
        self.w_p7_out = nn.Parameter(torch.ones(2, dtype=torch.float32))

    def _fast_fusion(self, weights, features):
        w = F.relu(weights)
        w_sum = torch.sum(w) + self.epsilon
        out = 0
        for i, feat in enumerate(features):
            out = out + (w[i] / w_sum) * feat
        return out

    def forward(self, inputs):
        # inputs: [P3, P4, P5, P6, P7] each of shape (B, num_channels, H_i, W_i)
        p3_in, p4_in, p5_in, p6_in, p7_in = inputs
        
        # Top-Down Pathway
        p6_td = self.conv6_td(self._fast_fusion(self.w_p6_td, [p6_in, F.interpolate(p7_in, size=p6_in.shape[2:], mode='nearest')]))
        p5_td = self.conv5_td(self._fast_fusion(self.w_p5_td, [p5_in, F.interpolate(p6_td, size=p5_in.shape[2:], mode='nearest')]))
        p4_td = self.conv4_td(self._fast_fusion(self.w_p4_td, [p4_in, F.interpolate(p5_td, size=p4_in.shape[2:], mode='nearest')]))
        
        # Bottom-Up Pathway
        p3_out = self.conv3_out(self._fast_fusion(self.w_p3_out, [p3_in, F.interpolate(p4_td, size=p3_in.shape[2:], mode='nearest')]))
        p4_out = self.conv4_out(self._fast_fusion(self.w_p4_out, [p4_in, p4_td, F.interpolate(p3_out, size=p4_in.shape[2:], mode='nearest')]))
        p5_out = self.conv5_out(self._fast_fusion(self.w_p5_out, [p5_in, p5_td, F.interpolate(p4_out, size=p5_in.shape[2:], mode='nearest')]))
        p6_out = self.conv6_out(self._fast_fusion(self.w_p6_out, [p6_in, p6_td, F.interpolate(p5_out, size=p6_in.shape[2:], mode='nearest')]))
        p7_out = self.conv7_out(self._fast_fusion(self.w_p7_out, [p7_in, F.interpolate(p6_out, size=p7_in.shape[2:], mode='nearest')]))
        
        return [p3_out, p4_out, p5_out, p6_out, p7_out]

if __name__ == "__main__":
    B, C = 2, 64
    bifpn = BiFPNBlock(num_channels=C)
    
    # Dummy multi-scale input features
    p3 = torch.randn(B, C, 64, 64)
    p4 = torch.randn(B, C, 32, 32)
    p5 = torch.randn(B, C, 16, 16)
    p6 = torch.randn(B, C, 8, 8)
    p7 = torch.randn(B, C, 4, 4)
    
    outputs = bifpn([p3, p4, p5, p6, p7])
    
    print(f"BiFPN Output P3 Shape: {outputs[0].shape}")
    print(f"BiFPN Output P7 Shape: {outputs[4].shape}")
    assert outputs[0].shape == (B, C, 64, 64)
    assert outputs[4].shape == (B, C, 4, 4)
    print("BiFPN Block verification successful!")
```

## 10. Strengths
- **State-of-the-Art Efficiency:** Achieves higher accuracy than previous detectors with up to $9\times$ fewer parameters and $13\times$ fewer FLOPs.
- **Principled Compound Scaling:** A single coefficient $\phi$ systematically scales the entire detector (Backbone, BiFPN, Head, Input Resolution).
- **Fast Normalized Feature Fusion:** Learns importance weights for feature branches dynamically without GPU computational overhead.

## 11. Weaknesses
- **Depthwise Conv Latency on Certain Hardware:** Depthwise separable convolutions are memory-bandwidth heavy; on older GPUs or microcontrollers without optimized depthwise kernels, inference can be slower than FLOP counts suggest.
- **Complex Parameter Scaling Rules:** Compound scaling requires building exact matched variants (D0 to D7).

## 12. Research Evolution
EfficientDet proved that compound scaling and weighted feature pyramids are essential for detection efficiency. It inspired **YOLOv6/v7**, **BiFPN variations in NAS**, and modern mobile detectors.

## 13. Interview Questions

**Q1: How does Fast Normalized Fusion in BiFPN differ from Softmax-based feature fusion?**
**A1:** Softmax fusion computes $O = \sum \frac{e^{w_i}}{\sum e^{w_j}} I_i$, which requires computing exponentials, making it slow on GPU hardware. Fast Normalized Fusion computes $O = \sum \frac{\text{ReLU}(w_i)}{\epsilon + \sum \text{ReLU}(w_j)} I_i$. It avoids exponential operations while enforcing $w_i \ge 0$, running $1.5\times$ to $2\times$ faster on GPUs with identical accuracy.

**Q2: What two structural optimizations does BiFPN make over traditional PANet?**
**A2:** (1) **Node Pruning:** Removes single-input nodes that perform no feature fusion to reduce parameters; (2) **Extra Residual Edge:** Adds a shortcut connection from the original input node to the output node at the same level if they reside at the same resolution, enabling extra feature reuse.

**Q3: How does EfficientDet's Compound Scaling differ from scaling just the backbone?**
**A3:** Scaling only the backbone creates a bottleneck in the feature pyramid or detection head. EfficientDet scales all four dimensions simultaneously using compound coefficient $\phi$: backbone choice, BiFPN width $W_{\text{bifpn}}$ & depth $D_{\text{bifpn}}$, head depth $D_{\text{head}}$, and input resolution $R_{\text{image}}$.

**Q4: Why does BiFPN use Depthwise Separable Convolutions instead of standard 3x3 convolutions?**
**A4:** Depthwise separable convolutions split standard convolution into depthwise spatial filtering and 1x1 pointwise channel projection, reducing parameters and FLOPs by $\sim 8\times$ to $9\times$ per layer while maintaining accuracy.

**Q5: What is the relation between compound coefficient $\phi$ and input resolution in EfficientDet?**
**A5:** Input resolution scales linearly with $\phi$: $R_{\text{image}} = 512 + \phi \cdot 128$. For D0 ($\phi=0$), $R=512$; for D1 ($\phi=1$), $R=640$; for D7 ($\phi=7$), $R=1536$.
