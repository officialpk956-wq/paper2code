# Fast R-CNN

## 1. Overview
Fast R-CNN, introduced in 2015 by Ross Girshick (Microsoft Research), revolutionized object detection by solving the critical computational inefficiency of original R-CNN. Instead of processing ~2,000 region proposals through 2,000 independent forward passes of a Convolutional Neural Network per image, Fast R-CNN processes the **entire image through the CNN once** to generate a single global feature map. It then introduces **Region of Interest Pooling (RoI Pooling)**—a novel layer that projects continuous region proposal coordinates directly onto the feature map and extracts fixed-size spatial feature vectors ($7 \times 7$) via grid-based max-pooling. Fast R-CNN also replaced the clunky multi-stage training pipeline (separate CNN, SVM, and Ridge Regressor) with a single **End-to-End Multi-Task Loss** that simultaneously optimizes classification (softmax cross-entropy) and bounding box regression (smooth $L_1$ loss). Fast R-CNN trained $9\times$ faster than R-CNN and achieved $213\times$ faster inference latency (~2.3 seconds per image).

:::tip
Fast R-CNN's fundamental rule: "Process the image once, crop features from the feature map, and train classification and regression jointly end-to-end."
:::

## 2. Historical Context
### The R-CNN → Fast R-CNN → Faster R-CNN Story: Eliminating Bottlenecks (Part 2)
In the grand evolution of two-stage object detectors, Fast R-CNN represents the decisive leap that made deep object detection practical.

Original R-CNN (2013) was notoriously slow (47 seconds/image) because it evaluated 2,000 independent CNN forward passes per image and stored hundreds of gigabytes of intermediate features on disk to train offline linear SVMs. 

In 2014, SPP-Net (Spatial Pyramid Pooling) showed that sharing a single feature map across proposals could speed up inference. However, SPP-Net had a major limitation: **It could not update the convolutional layers below the SPP layer during backpropagation.** SPP-Net's fine-tuning was restricted to fully connected layers because backpropagating through SPP across proposals from different images was computationally inefficient.

Ross Girshick invented **Fast R-CNN** to solve both the feature sharing bottleneck AND the fine-tuning bottleneck. He designed **RoI Pooling** (a simplified single-scale variant of SPP) and proposed a novel **Hierarchical Mini-Batch Sampling** technique (sampling $N=2$ images per mini-batch and $R=64$ proposals per image). This allowed backpropagation to efficiently flow through RoI Pooling all the way down to the early convolutional layers.

However, Fast R-CNN left one final bottleneck untouched: **Selective Search**. Generating 2,000 proposals on CPU still took **2 seconds per image**, whereas Fast R-CNN's GPU execution took only 0.3 seconds. This remaining CPU proposal bottleneck directly inspired **Faster R-CNN** (2015).

## 3. Problem It Solves
Fast R-CNN solves three major deficiencies of earlier object detection systems:
1. **Redundant Feature Computation:** Eliminates 2,000 redundant CNN passes per image by computing a single full-image feature map and extracting RoI features on demand.
2. **Multi-Stage Disjoint Training Pipeline:** Replaces offline SVMs and separate ridge regressors with a unified **Multi-Task Loss** ($\mathcal{L}_{\text{cls}} + \mathcal{L}_{\text{loc}}$), enabling single-stage end-to-end backpropagation.
3. **SPP-Net Fine-Tuning Restriction:** Enables end-to-end gradient backpropagation through RoI Pooling down to the deep convolutional layers via Hierarchical Mini-Batch Sampling.

## 5. Layer-by-Layer Breakdown
Fast R-CNN streamlines the object detection pipeline into a single unified network:

**1. Full-Image CNN Backbone (e.g., VGG-16):**
- Takes an RGB image of size $3 \times H \times W$.
- Passes the full image through 13 convolutional layers (VGG-16) to output a global feature map of shape $512 \times H/16 \times W/16$.

**2. RoI Pooling Layer:**
- Takes the continuous RoI proposal coordinates $(x_1, y_1, x_2, y_2)$ from Selective Search.
- Projects the coordinates onto the $H/16 \times W/16$ feature map by dividing by stride $S=16$ and rounding ($\lfloor x/16 \rfloor$).
- Divides the sub-region into a fixed $H_{\text{out}} \times W_{\text{out}}$ grid (typically $7 \times 7$) and applies max-pooling in each bin.
- Outputs a uniform tensor of shape $(N_{\text{roi}}, 512, 7, 7)$.

**3. Shared Fully Connected Layers (FC6 & FC7):**
- Flattens each $512 \times 7 \times 7$ tensor into a 25,088-d vector.
- Processes vectors through two 4096-dimensional dense layers (`fc6` and `fc7`) with ReLU and Dropout (0.5).

**4. Dual Multi-Task Prediction Heads:**
- **Classification Branch:** A linear layer mapping 4096-d features to $K+1$ outputs (where $K$ is the number of classes and $+1$ represents background). Computes softmax probabilities $p = (p_0, p_1, \dots, p_K)$.
- **Bounding Box Regression Branch:** A linear layer mapping 4096-d features to $(K+1) \times 4$ outputs. Predicts class-specific spatial refinement deltas $t^k = (t_x^k, t_y^k, t_w^k, t_h^k)$ for each class $k$.

## 6. Tensor Flow Walkthrough
Let's trace tensors for a single mini-batch with $N=2$ images, $R=128$ total proposals (64 per image), $K=20$ classes (PASCAL VOC), and a VGG-16 backbone.

1. **Full-Image Feature Extraction:**
   - Input Image Batch: `(2, 3, 600, 800)`
   - VGG-16 Backbone $\rightarrow$ Global Feature Map: `(2, 512, 38, 50)` (where $600/16 = 37.5 \rightarrow 38$, $800/16 = 50$)
2. **RoI Projection & Selection:**
   - Total Selected RoIs: `(128, 5)` where each row is `(image_index, x1, y1, x2, y2)`.
3. **RoI Pooling Execution:**
   - Projects RoI coordinates onto feature map space: `RoI / 16`.
   - Divides each RoI region into $7 \times 7$ grid bins and performs max pooling.
   - Output Tensor: `(128, 512, 7, 7)`
4. **Shared Dense Feature Representation:**
   - Flatten: `(128, 25088)`
   - FC6 + ReLU: `(128, 4096)`
   - FC7 + ReLU: `(128, 4096)`
5. **Multi-Task Predictions:**
   - **Classifier Head:** Linear(4096 $\rightarrow 21$) $\rightarrow$ `(128, 21)` logits. Apply Softmax $\rightarrow$ `(128, 21)` probabilities.
   - **BBox Head:** Linear(4096 $\rightarrow 84$) $\rightarrow$ `(128, 84)` deltas ($21 \times 4 = 84$).
6. **Multi-Task Loss Computation:**
   - $\mathcal{L}_{\text{cls}}$ (Cross-Entropy over 21 classes) + $\mathcal{L}_{\text{loc}}$ (Smooth $L_1$ over true class deltas).

## 7. Mathematical Foundations

### 1. RoI Pooling Quantization Formulation
Let an RoI on the original image be defined as continuous bounds $(x_1, y_1, w, h)$.
The projected RoI bounds on a feature map with stride $S=16$ are quantized by integer floor:
$$x_1' = \lfloor x_1 / S \rfloor, \quad y_1' = \lfloor y_1 / S \rfloor$$
$$w' = \lfloor w / S \rfloor, \quad h' = \lfloor h / S \rfloor$$

The feature sub-region of size $w' \times h'$ is partitioned into a grid of $H_{\text{out}} \times W_{\text{out}}$ sub-windows (bins) of approximate size $H_{\text{bin}} \times W_{\text{bin}}$:
$$H_{\text{bin}} = h' / H_{\text{out}}, \quad W_{\text{bin}} = w' / W_{\text{out}}$$

For bin $(i, j)$ defined over spatial coordinates $r(i, j)$, RoI max-pooling outputs value $y_{i,j}$:
$$y_{i,j} = \max_{(x,y) \in r(i,j)} x(x, y)$$

### 2. Multi-Task Loss Function
Each labeled RoI is annotated with a ground-truth class $u \in \{0, 1, \dots, K\}$ (where $u=0$ is background) and a ground-truth bounding box regression target $v = (v_x, v_y, v_w, v_h)$.

The multi-task loss $\mathcal{L}$ combines classification loss $\mathcal{L}_{\text{cls}}$ and bounding box regression loss $\mathcal{L}_{\text{loc}}$:

$$\mathcal{L}\left(p, u, t^u, v\right) = \mathcal{L}_{\text{cls}}(p, u) + \lambda [u \ge 1] \mathcal{L}_{\text{loc}}\left(t^u, v\right)$$

where $[u \ge 1]$ is an Iverson bracket evaluated to $1$ when $u \ge 1$ (foreground object) and $0$ when $u=0$ (background, for which regression loss is ignored).

- **Classification Loss:** Standard log loss for true class $u$:
  $$\mathcal{L}_{\text{cls}}(p, u) = -\log p_u$$

- **Bounding Box Loss:** Sum of Smooth $L_1$ losses over the 4 box tuple coordinates:
  $$\mathcal{L}_{\text{loc}}\left(t^u, v\right) = \sum_{i \in \{x, y, w, h\}} \text{smooth}_{L1}\left(t_i^u - v_i\right)$$

- **Smooth $L_1$ Function:** A robust $L_1$-like loss that is less sensitive to outliers than $L_2$ loss:
  $$\text{smooth}_{L1}(x) = \begin{cases} 0.5 x^2 & \text{if } |x| < 1 \\ |x| - 0.5 & \text{otherwise} \end{cases}$$

## 8. Training Procedure
- **Hierarchical Mini-Batch Sampling:** Mini-batches are constructed hierarchically. During each SGD iteration, $N=2$ images are sampled, and $R=64$ proposals are sampled from each image, producing a mini-batch of $R_{\text{total}} = 128$ RoIs. Features for RoIs from the same image are shared in GPU memory, drastically lowering memory traffic and training latency.
- **Positive/Negative Balance:** Mini-batches consist of 25% foreground RoIs ($\text{IoU} \ge 0.5$ with ground-truth) and 75% background RoIs ($0.1 \le \text{IoU} < 0.5$).
- **Optimizer:** SGD with momentum 0.9, weight decay $5 \times 10^{-4}$. Trained for 30k iterations on PASCAL VOC with learning rate 0.001, stepping down to 0.0001 at 20k iterations.

## 9. PyTorch Implementation
Here is a complete, self-contained PyTorch implementation of Fast R-CNN featuring an RoI Pooling layer and dual multi-task heads.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from torchvision.ops import RoIPool

class FastRCNN(nn.Module):
    def __init__(self, num_classes=20, spatial_scale=1.0/16.0, pooled_size=7):
        super().__init__()
        self.num_classes = num_classes
        
        # Mock Backbone: Simulates VGG-16 output (512 channels, stride 16)
        self.backbone = nn.Sequential(
            nn.Conv2d(3, 64, kernel_size=3, padding=1),
            nn.ReLU(inplace=True),
            nn.MaxPool2d(2, 2),
            nn.Conv2d(64, 512, kernel_size=3, padding=1),
            nn.ReLU(inplace=True),
            nn.MaxPool2d(8, 8) # Total stride = 16
        )
        
        # RoI Pooling Layer (Torchvision native)
        self.roi_pool = RoIPool(output_size=(pooled_size, pooled_size), spatial_scale=spatial_scale)
        
        # Shared Dense Classifier (FC6 and FC7)
        self.shared_fc = nn.Sequential(
            nn.Linear(512 * pooled_size * pooled_size, 4096),
            nn.ReLU(inplace=True),
            nn.Dropout(p=0.5),
            nn.Linear(4096, 4096),
            nn.ReLU(inplace=True),
            nn.Dropout(p=0.5)
        )
        
        # Multi-Task Prediction Heads
        self.cls_score = nn.Linear(4096, num_classes + 1)      # K + 1 classes (with background)
        self.bbox_pred = nn.Linear(4096, (num_classes + 1) * 4) # (K + 1) * 4 deltas

    def forward(self, images, rois):
        """
        images: (B, 3, H, W)
        rois: (N_roi, 5) tensor where each row is (image_batch_idx, x1, y1, x2, y2)
        """
        # 1. Full-image feature extraction (processed ONCE per batch)
        feature_map = self.backbone(images) # (B, 512, H/16, W/16)
        
        # 2. RoI Pooling
        pooled_features = self.roi_pool(feature_map, rois) # (N_roi, 512, 7, 7)
        
        # 3. Shared Dense Layers
        flattened = torch.flatten(pooled_features, 1)     # (N_roi, 25088)
        roi_vectors = self.shared_fc(flattened)            # (N_roi, 4096)
        
        # 4. Multi-Task Heads
        cls_logits = self.cls_score(roi_vectors)          # (N_roi, K + 1)
        bbox_deltas = self.bbox_pred(roi_vectors)          # (N_roi, (K + 1) * 4)
        
        return cls_logits, bbox_deltas

def fast_rcnn_loss(cls_logits, bbox_deltas, gt_labels, gt_deltas, lambda_reg=1.0):
    """
    cls_logits: (N_roi, K+1)
    bbox_deltas: (N_roi, (K+1)*4)
    gt_labels: (N_roi,) long tensor of class indices
    gt_deltas: (N_roi, 4) targets for regression
    """
    # 1. Classification Loss (Cross Entropy)
    loss_cls = F.cross_entropy(cls_logits, gt_labels)
    
    # 2. Regression Loss (Smooth L1) - Only for positive non-background RoIs (gt_labels >= 1)
    pos_mask = (gt_labels >= 1)
    if pos_mask.sum() > 0:
        pos_idx = torch.nonzero(pos_mask).squeeze(1)
        pos_labels = gt_labels[pos_idx]
        
        # Extract predictions for the true positive class
        # Reshape deltas to (N_roi, K+1, 4)
        bbox_pred_reshaped = bbox_deltas.view(-1, cls_logits.shape[1], 4)
        pos_bbox_pred = bbox_pred_reshaped[pos_idx, pos_labels] # (N_pos, 4)
        pos_gt_deltas = gt_deltas[pos_idx]                     # (N_pos, 4)
        
        loss_loc = F.smooth_l1_loss(pos_bbox_pred, pos_gt_deltas, reduction='sum') / cls_logits.shape[0]
    else:
        loss_loc = torch.tensor(0.0, device=cls_logits.device)
        
    total_loss = loss_cls + lambda_reg * loss_loc
    return total_loss, loss_cls, loss_loc

if __name__ == "__main__":
    num_classes = 20
    model = FastRCNN(num_classes=num_classes)
    
    # Dummy Input Images (2, 3, 600, 800)
    dummy_images = torch.randn(2, 3, 600, 800)
    # Dummy RoIs: 4 RoIs total (2 from image 0, 2 from image 1)
    # Format: [batch_index, x1, y1, x2, y2]
    dummy_rois = torch.tensor([
        [0, 10.0, 10.0, 200.0, 200.0],
        [0, 50.0, 50.0, 400.0, 300.0],
        [1, 100.0, 100.0, 500.0, 500.0],
        [1, 300.0, 200.0, 600.0, 550.0]
    ], dtype=torch.float32)
    
    cls_logits, bbox_deltas = model(dummy_images, dummy_rois)
    
    print(f"Classification Logits Shape: {cls_logits.shape}")
    print(f"Bounding Box Deltas Shape:   {bbox_deltas.shape}")
    
    assert cls_logits.shape == (4, num_classes + 1), f"Expected (4, {num_classes + 1}), got {cls_logits.shape}"
    assert bbox_deltas.shape == (4, (num_classes + 1) * 4), f"Expected (4, {(num_classes + 1) * 4}), got {bbox_deltas.shape}"
    
    # Test Multi-Task Loss Computation
    dummy_labels = torch.tensor([1, 0, 5, 0], dtype=torch.long) # RoIs 0 and 2 are positive
    dummy_gt_deltas = torch.randn(4, 4)
    total_loss, l_cls, l_loc = fast_rcnn_loss(cls_logits, bbox_deltas, dummy_labels, dummy_gt_deltas)
    
    print(f"Total Multi-Task Loss: {total_loss.item():.4f} (Cls: {l_cls.item():.4f}, Loc: {l_loc.item():.4f})")
    print("Fast R-CNN verification successful!")
```

## 10. Strengths
- **Massive Speedup over R-CNN:** $9\times$ faster training time and $213\times$ faster test-time inference (0.3s GPU execution time per image).
- **Single-Stage Joint Training:** Single multi-task loss optimizes classification and bounding box regression end-to-end in a single training run.
- **No Disk Storage Requirement:** Eliminates intermediate feature disk storage, training entirely in GPU RAM.
- **Higher Accuracy:** Achieving higher mAP (66.9% on VOC 2007) than R-CNN and SPP-Net because backpropagation updates early convolutional layers.

## 11. Weaknesses
- **CPU Proposal Bottleneck Remains:** Still relies on external Selective Search on CPU to generate ~2,000 region proposals, which takes ~2 seconds per image—dwarfing Fast R-CNN's GPU execution time (0.3s).
- **RoI Pooling Quantization Errors:** Integer rounding in RoI Pooling ($\lfloor x/16 \rfloor$) introduces spatial misalignment, which degrades fine pixel-level mask prediction (later fixed by RoIAlign in Mask R-CNN).

## 12. Research Evolution
Fast R-CNN unified classification and bounding box regression into a single multi-task loss network, proving that feature map sharing is essential for real-time object recognition. However, its dependence on CPU-based Selective Search motivated Ren et al. to invent **Faster R-CNN** (2015), which replaced Selective Search with a GPU-based Region Proposal Network (RPN).

## 13. Interview Questions

**Q1: What is the main difference between SPP-Net and Fast R-CNN regarding gradient backpropagation?**
**A1:** SPP-Net could not update convolutional layers below the SPP layer during fine-tuning because proposals came from many different images in a mini-batch, making gradient computation through SPP extremely inefficient. Fast R-CNN solved this by introducing **Hierarchical Mini-Batch Sampling** (sampling $N=2$ images per batch and $R=64$ proposals per image), enabling backpropagation to update all convolutional layers end-to-end.

**Q2: How does RoI Pooling work mathematically?**
**A2:** RoI Pooling projects continuous bounding box coordinates $(x_1, y_1, w, h)$ onto a feature map with stride $S=16$ by integer rounding: $x_1' = \lfloor x_1 / S \rfloor, w' = \lfloor w / S \rfloor$. The $w' \times h'$ feature region is divided into a fixed $H_{\text{out}} \times W_{\text{out}}$ grid (e.g., $7 \times 7$), and standard max-pooling is applied independently inside each bin to output a uniform $H_{\text{out}} \times W_{\text{out}}$ tensor.

**Q3: Explain the Smooth $L_1$ loss used in Fast R-CNN bounding box regression.**
**A3:** Smooth $L_1$ loss is quadratic for small errors ($|x| < 1$, where $\text{smooth}_{L1}(x) = 0.5 x^2$) and linear for large errors ($|x| \ge 1$, where $\text{smooth}_{L1}(x) = |x| - 0.5$). Unlike standard $L_2$ loss (which can explode when gradients from large regression outliers occur), Smooth $L_1$ limits gradient magnitudes to 1 for large errors, preventing gradient explosion.

**Q4: Why does Fast R-CNN multiply the localization loss $\mathcal{L}_{\text{loc}}$ by the Iverson bracket $[u \ge 1]$?**
**A4:** The Iverson bracket $[u \ge 1]$ evaluates to $1$ when the RoI's true ground-truth class $u \ge 1$ (a foreground object class) and $0$ when $u=0$ (background). Background RoIs have no ground-truth bounding box, so regression loss is ignored for background samples.

**Q5: What was the remaining runtime bottleneck in Fast R-CNN that prevented true real-time detection?**
**A5:** While Fast R-CNN's GPU execution took only ~0.3 seconds per image, generating 2,000 region proposals using CPU-based Selective Search took **~2.0 seconds per image**, accounting for over 85% of total test-time latency.
