# AI Fraud Detection System Design

<Callout type="tip" title="Key Insight">
Fraud detection is a race against time. Fraudsters move fast, utilizing coordinated rings and stolen identities. A modern AI fraud system must process thousands of transactions per second, calculate complex historical features in real-time, and analyze hidden network relationships using Graph Neural Networks.
</Callout>

## The Streaming Feature Pipeline

When a user swipes a credit card, the transaction must be approved or declined in less than 200 milliseconds. However, the model doesn't just look at the raw swipe amount; it needs context. 

This context is built using a streaming architecture:
- **Event Bus (Kafka):** All transactions, logins, and profile updates are pushed into a highly durable Kafka stream.
- **Stream Processing (Flink):** Apache Flink reads the Kafka stream in real-time and calculates aggregations over sliding time windows. For example, it tracks "Number of failed login attempts in the last 10 minutes" or "Standard deviation of purchase amounts in the last hour."
- **Online Feature Store (Redis):** Flink pushes these calculated features into a low-latency database, so when a new transaction occurs, the model can instantly pull the user's latest streaming features.

## Graph Anomaly Detection

Traditional Machine Learning (like XGBoost) looks at tabular rows. But fraud is inherently relational. Fraud rings often share device IDs, IP addresses, or shipping addresses across hundreds of seemingly independent accounts.

**Graph Neural Networks (GNNs)** excel here. By modeling users, devices, and transactions as nodes in a graph, and their interactions as edges, a GNN can perform *Message Passing*. 

If User A has a high fraud probability, the GNN passes that risk score along the network's edges. If User B shares a device ID with User A, User B's risk score immediately increases, even if User B's individual transactions look perfectly normal. This allows the system to catch coordinated synthetic identity rings.

## Model Refresh Cadence

Fraud is highly adversarial. If you deploy a model that blocks a specific exploit, the fraudsters will figure out the new rules within weeks and change their behavior (extreme Concept Drift).

Therefore, fraud models require an aggressive **Model Refresh Cadence**:
- **Daily Re-training:** Models are often automatically retrained every night on the previous day's labels to catch rapidly shifting attack vectors.
- **Ensemble Systems:** Financial institutions don't rely on a single model. They use an ensemble of slow-updating models (for long-term stability) combined with fast-updating models (to catch immediate spikes in specific fraud patterns).
