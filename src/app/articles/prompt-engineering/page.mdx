# Prompt Engineering: Unlocking LLM Capabilities

<Callout type="tip" title="Key Insight">
Large Language Models are massive probability engines trying to predict the next word. Prompt engineering is the art of providing the right context, structure, and constraints to steer those probabilities toward the exact output format, tone, and reasoning path you require.
</Callout>

## Zero-Shot and Few-Shot Prompting

**Zero-Shot** prompting involves asking the model to perform a task without providing any examples. Thanks to instruction-tuning (like RLHF), modern models like GPT-4 or Claude 3 excel at zero-shot translation, summarization, and coding.

However, when you need a highly specific output format or tone, you use **Few-Shot Prompting** (also called In-Context Learning). By providing a few examples (typically 3 to 5) of the input-output mapping directly in the prompt, the model instantly adapts to the pattern without any weight updates.

## Chain-of-Thought (CoT) Reasoning

For complex math or logic puzzles, standard prompting often fails. The model tries to generate the final answer immediately, forcing it to perform complex internal reasoning in a single forward pass.

The **Chain-of-Thought (CoT)** technique (Wei et al., 2022) solved this. By simply appending the phrase "Let's think step by step" to the prompt, or by providing few-shot examples that include intermediate reasoning steps, the model generates its "scratchpad" of thought. 

Because LLMs are autoregressive (they feed their output back in as input for the next token), generating intermediate reasoning tokens allows the model to "talk itself" into the correct answer. The original paper showed CoT was an emergent ability that only appeared in massive models (typically >100B parameters).

## Advanced Prompting Techniques

As LLMs evolved, so did the strategies to constrain and guide them:

- **Self-Consistency:** Generate multiple different Chain-of-Thought reasoning paths for the same question, then take a majority vote. Research shows a majority vote of $k=40$ paths can significantly boost accuracy on benchmarks like GSM8K.
- **Tree-of-Thought (ToT):** Extends CoT by allowing the model to explore multiple reasoning branches, evaluate the promise of each branch, and backtrack if a path hits a dead end.
- **Structured Output Prompting:** Forcing the LLM to reply strictly in JSON or XML format. Supplying a schema in the system prompt prevents the model from adding conversational filler like "Here is your JSON:" which breaks parsing code.

## System vs User Prompts

Modern LLM APIs separate prompts into roles:
1. **System Prompt:** Sets the global behavior, persona, and strict constraints (e.g., "You are an expert Python developer. Reply only with valid code. Do not explain."). The model is weighted to treat these instructions as the highest priority.
2. **User Prompt:** The actual task or data provided by the human at runtime.

## Parameters: Temperature and Top-P

Prompt engineering isn't just text; it's also API parameters. 
- **Temperature ($T$)** scales the logits before the softmax function. $T = 0$ makes the model completely deterministic and greedy (best for coding and logic). Higher temperatures (e.g., $T = 0.8$) flatten the distribution, increasing randomness and creativity (best for brainstorming).
- **Top-P (Nucleus Sampling)** truncates the probability distribution. A `top_p` of 0.9 means the model only considers the smallest set of words whose cumulative probability exceeds 90%, cutting off the absurdly rare "long tail" tokens.
