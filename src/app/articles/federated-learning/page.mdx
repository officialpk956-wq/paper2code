# Federated Learning: Privacy-Preserving AI

<Callout type="tip" title="Key Insight">
Traditional ML requires centralizing all data in a massive data warehouse. Federated Learning flips this paradigm: instead of bringing the data to the model, it brings the model to the data, ensuring extreme privacy for sensitive information like medical records or personal text messages.
</Callout>

## The FedAvg Algorithm

The foundational algorithm of Federated Learning is **Federated Averaging (FedAvg)**. 

Instead of a central server training a model, the server broadcasts the current model weights to thousands of edge devices (like smartphones). Each device uses its own local, private data to perform several steps of Stochastic Gradient Descent (SGD). 

The devices then send their *updated weights* (or gradients) back to the central server. The server averages all these updates together to create a new, smarter global model, and the cycle repeats. The raw data never leaves the device.

## The Non-IID Data Challenge

In a traditional datacenter, training data is perfectly shuffled (Independent and Identically Distributed, or IID). 

In Federated Learning, data is highly **non-IID**. One user might only type in Spanish, while another types in English. One user's medical imagery might come from an MRI, another from a CT scan. If a model trains too long on a local device, it will overfit entirely to that user's specific data distribution, causing the global model to diverge when averaged.

Algorithms like **FedProx** solve this by adding a proximal term to the loss function, mathematically penalizing the local model if its weights stray too far from the global server model.

## Communication Efficiency

Neural networks are massive files (often hundreds of megabytes or gigabytes). Sending these models back and forth over thousands of weak 4G/5G connections is a major bottleneck.

Researchers use extreme compression techniques to solve this:
- **Sparsification:** Only sending the top 1% of gradients (the ones that changed the most) back to the server.
- **Gradient Quantization:** Compressing the 32-bit float updates down to 8-bit or even 1-bit representations before transmission.

## Differential Privacy

Even if raw data isn't transmitted, a clever attacker could theoretically analyze the gradients sent by a phone to reverse-engineer what the user typed. 

**Differential Privacy (DP-SGD)** prevents this. Before the device sends its gradients back to the server, it explicitly adds statistically calibrated Gaussian noise to the weights. This noise mathematically obscures the contribution of any single data point, making it impossible to reverse-engineer an individual's data, while still allowing the server to learn broad, population-level trends.

## Cross-Silo vs Cross-Device

Federated Learning deployment falls into two categories:
- **Cross-Device:** Millions of unreliable endpoints (smartphones, IoT devices). Devices frequently drop offline, and the server must handle immense scale and battery constraints. Used heavily by Google (Gboard prediction) and Apple (QuickType).
- **Cross-Silo:** A small number (2 to 100) of highly reliable, powerful servers. Often used by consortiums of hospitals sharing medical models without legally sharing HIPAA-protected patient records.
