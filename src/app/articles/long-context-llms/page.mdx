# Long Context LLMs: From 2K to 2 Million Tokens

<Callout type="tip" title="Key Insight">
The original Transformer architecture has an Achilles' heel: the self-attention mechanism scales quadratically ($O(N^2)$) with the sequence length. Doubling the context window requires quadrupling the memory and compute. Scaling context windows to millions of tokens required fundamental breakthroughs in both mathematics and distributed systems.
</Callout>

## Positional Interpolation (YaRN)

Language models use Positional Embeddings (specifically RoPE - Rotary Position Embeddings) to know the order of words. If a model was trained on 4K tokens, it has never seen position `4001`. If you try to feed it an 8K prompt, it fails catastrophically because it doesn't know how to handle the new positional coordinates.

Instead of extrapolating to unknown positions, researchers developed **Positional Interpolation**. They mathematically squish the 8K positions to fit within the 4K coordinate space the model already knows. Advanced techniques like **YaRN** (Yet another RoPE extensioN) apply this interpolation non-linearly, preserving the high-frequency local details while squishing the low-frequency global distances. This allows a model trained on 4K tokens to instantly understand 32K tokens without re-training from scratch.

## Breaking the $O(N^2)$ Barrier: Sliding Windows

For extreme context (like 100K+ tokens), even interpolated RoPE isn't enough; the GPU simply runs out of VRAM trying to compute the massive attention matrix. 

Models like **Mistral** and **Longformer** use **Sliding Window Attention**. Instead of every token paying attention to every other token in the document, a token only pays attention to its immediate neighbors (e.g., a window of 4,096 tokens). Because layers are stacked, information still flows across the entire document (token 1 influences token 4000 in layer 1, which influences token 8000 in layer 2). This reduces the complexity from quadratic to linear ($O(N \times W)$).

## Ring Attention: Sequence Parallelism

When Google announced Gemini 1.5 Pro with a **1 million token context window**, the entire AI community was stunned. A 1M token KV cache for a massive model cannot physically fit on a single GPU (or even a single 8-GPU node). 

To solve this, researchers developed **Ring Attention**, a form of sequence parallelism.

<SVGDiagram src="/diagrams/long-context-llms.svg" caption="Ring Attention distributes a massive sequence across multiple GPUs." />

In Ring Attention, the 1M token sequence is chopped into chunks (e.g., 250K tokens per GPU). Each GPU computes the attention for its local chunk. Then, the GPUs pass their Key-Value (KV) blocks in a ring to the next GPU over the high-speed NVLink network. As the blocks cycle through the ring, every GPU eventually computes exact attention against every other token, without any single GPU needing enough RAM to hold the entire sequence.

## The "Lost in the Middle" Phenomenon

Just because a model *can* ingest 1 million tokens doesn't mean it uses them well. Researchers discovered the **"Lost in the Middle"** phenomenon. 

If you hide a specific fact inside a 100K document, an LLM will easily find it if it is at the very beginning (the primacy effect) or the very end (the recency effect). But if the fact is buried precisely in the middle of the document, retrieval accuracy plummets. When building RAG systems with long-context models, engineers must actively re-order chunks so the most relevant information is pushed to the edges of the prompt.
