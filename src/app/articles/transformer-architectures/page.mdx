# Transformer Architectures: BERT, GPT, T5 and Beyond

<Callout type="tip" title="Key Insight">
The 2017 Transformer paper introduced one architecture. By 2019, three distinct families had emerged from it — BERT, GPT, and T5 — each using only part of the original design. Every major AI system in use today traces directly to one of these three families. Understanding the differences between them is understanding modern AI.
</Callout>

## The Original Transformer (2017)

Vaswani et al.'s "Attention Is All You Need" eliminated recurrence from sequence modeling. The key idea: **self-attention** lets every position in a sequence attend to every other position directly, without processing tokens sequentially.

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

The query ($Q$), key ($K$), and value ($V$) matrices are learned linear projections of the input. For each position, attention computes how relevant every other position is (the $QK^T$ dot product), normalizes with softmax, and takes a weighted sum of values.

The original architecture had an **encoder** (processes the full input sequence in parallel using bidirectional attention) and a **decoder** (generates output tokens one at a time using causal — left-to-right — attention, plus cross-attention to the encoder output). It was designed for machine translation.

## Family 1 — Encoder-Only: BERT

**BERT (Devlin et al., 2018)** kept only the encoder and invented a new pretraining task: **Masked Language Modeling (MLM)**. 15% of tokens are randomly masked, and the model must predict the original tokens from context. Because the encoder can attend to all positions (both left and right of the mask), BERT learns deep bidirectional representations.

BERT achieved state-of-the-art on 11 NLP tasks simultaneously upon release. For the first time, a single pretrained model could be fine-tuned on any NLP task by adding a small task-specific head.

**When to use encoder-only models:** tasks that require understanding the full input — classification, named entity recognition, question answering (extracting a span from a document), semantic similarity. The encoder's bidirectional attention is perfect for tasks where you need to understand a fixed input. BERT can't generate text because it has no decoder.

**The BERT family:**
- **RoBERTa (2019)** — BERT trained longer with larger batches, no NSP task, dynamic masking. Removed weaknesses in BERT's training recipe.
- **ALBERT (2019)** — Factorized embedding + cross-layer parameter sharing. 18× fewer parameters, same performance. For mobile/edge NLU.
- **DistilBERT (2019)** — Knowledge distillation: a 6-layer student trained to mimic 12-layer BERT. 40% smaller, 60% faster, 97% BERT quality.
- **DeBERTa (2020)** — Disentangled attention: position and content encoded separately. Won SuperGLUE.

## Family 2 — Decoder-Only: GPT

**GPT (Radford et al., 2018)** kept only the decoder and used **causal language modeling** as the pretraining task: predict the next token given all previous tokens. Causal attention (each token can only attend to previous positions) is what enables generation — you generate one token at a time, and each new token is conditioned on all previous tokens.

GPT-1 (117M parameters) demonstrated that decoder-only pretraining enables zero-shot and few-shot performance on downstream tasks without task-specific fine-tuning. **In-context learning** — providing examples in the prompt — teaches the model the task format without any gradient updates.

**When to use decoder-only models:** any generation task — text completion, question answering via generation, code generation, summarization, creative writing, dialogue. Every major LLM (GPT-4, Llama, Claude, Gemini) uses the decoder-only architecture. Decoder models can also do classification by generating the class label as a token.

**The GPT/LLM family:**
- **GPT-2 (2019)** — 1.5B parameters. Demonstrated that scale enables qualitatively better few-shot generation. Initially withheld as "too dangerous."
- **GPT-3 (2020)** — 175B parameters. Emergent few-shot capabilities: perform tasks never trained on by seeing 3 examples in the prompt.
- **Llama (2023)** — 7B–65B open-weight decoder models trained on publicly available data. Outperformed GPT-3 at a fraction of the size by training on higher-quality data for longer.
- **Mistral 7B (2023)** — Sliding window attention (attend to only the nearest 4K tokens per layer) + grouped query attention. Outperformed Llama 2 13B at 7B parameters.
- **Mixtral 8×7B (2023)** — MoE decoder: 8 expert feedforward networks, 2 activated per token. GPT-3.5 quality at 12B active parameters.

<Callout type="info" title="Why Decoder-Only Won">
The original Transformer had both encoder and decoder because translation needs both: the encoder processes the source language, the decoder generates the target language. For tasks like "summarize this document" or "answer this question," you can frame everything as text-to-text generation — just put the input in the prompt and generate the output. The decoder-only architecture is more flexible because it unifies all NLP tasks as next-token prediction, while encoder-only models are limited to tasks where you understand a fixed input.
</Callout>

## Family 3 — Encoder-Decoder: T5 and BART

**T5 (Raffel et al., 2019)** kept the full encoder-decoder architecture and introduced the **text-to-text framework**: every NLP task is expressed as "convert this input text to this output text." Translation is "translate English to German: [text]". Summarization is "summarize: [text]". Classification is "classify sentiment: [text]" and the model outputs "positive" or "negative" as text.

T5's insight: a single sequence-to-sequence model can be pretrained on all tasks simultaneously because they all reduce to text-to-text. This unified approach produced a model that could be fine-tuned on any task with minimal task-specific engineering.

**When to use encoder-decoder models:** tasks with explicit input → output structure where the output has different length and format than the input: translation, summarization, question generation, structured extraction. The encoder processes the full input with bidirectional attention (understanding), and the decoder generates the output with cross-attention to the encoder (generation conditioned on full understanding).

**BART (Lewis et al., 2019)** pretrains the encoder-decoder architecture with a denoising objective: corrupt the input in various ways (masking, deletion, permutation) and train the model to reconstruct the original. BART is particularly strong at generation tasks because it's explicitly pretrained to reconstruct fluent text.

## The Attention Mechanism Variants

As the Transformer scaled, the core attention mechanism became a bottleneck. Several variants reduce its $O(n^2)$ complexity:

**Multi-Query Attention (MQA)** — Share a single key and value head across all query heads. Reduces KV cache size proportionally, enabling longer sequences at fixed memory.

**Grouped Query Attention (GQA)** — Share K/V heads across groups of Q heads. Middle ground between standard MHA and MQA. Used in Llama 2/3, Mistral.

**Sliding Window Attention** — Each token attends only to the nearest $w$ tokens. O(n×w) instead of O(n²). Used in Mistral, Longformer.

**Flash Attention** — Not a new mechanism, but a hardware-aware implementation that fuses operations to stay in GPU SRAM, avoiding expensive HBM reads/writes. 2–4× faster, enables longer sequences. Now the standard implementation in all major frameworks.

## What Came After: Vision and Multimodal

The Transformer's success in NLP raised the question: does self-attention work for images?

**ViT (Dosovitskiy et al., 2020)** answered yes. Split a 224×224 image into 16×16 patches, linearly embed each patch as a token, prepend a [CLS] classification token, and run the standard Transformer encoder. With enough data (JFT-300M), ViT outperforms CNNs on ImageNet.

**CLIP (Radford et al., 2021)** extended the Transformer to cross-modal learning: a Vision Transformer for images and a text Transformer for captions, trained with a contrastive loss that pulls matching image-text pairs together and pushes non-matching pairs apart. The resulting embedding space supports zero-shot image classification, image search by text, and text-to-image generation.

**GPT-4o (2024)** is the endpoint of this progression: a single decoder-only model that processes text, images, and audio natively, trained jointly on all modalities. The architecture is a single Transformer that accepts arbitrary interleaved sequences of modality tokens.

## Practice

<Callout type="info">
For hands-on understanding: implement multi-head self-attention from scratch in PyTorch (the Q, K, V projections, dot product, softmax, and output projection). Causal masking is a single line: `mask = torch.tril(torch.ones(seq_len, seq_len))`. Once you can implement one attention head, stacking multiple heads and adding the feedforward layer gives you the full Transformer block.
</Callout>
