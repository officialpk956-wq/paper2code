# AI Search System Design

<Callout type="tip" title="Key Insight">
Modern search is no longer just matching exact keywords. By combining traditional lexical search (BM25) with semantic vector search and aggressive machine-learning-based re-ranking, AI search engines can understand the *intent* of a query, not just the text.
</Callout>

## Query Understanding

The search pipeline begins the millisecond a user hits "enter". Before touching a database, the system must understand the query:
- **Spellcheck & Normalization:** Correcting typos using fast edit-distance algorithms or lightweight Seq2Seq models.
- **Intent & Entity Extraction:** Using a fast NLP model (like a fine-tuned BERT) to tag entities. For example, in the query "Apple laptops under $1000", the system tags `Brand: Apple`, `Category: Laptops`, and `Price: <1000`.

## Hybrid Retrieval

Once the query is understood, the system retrieves a broad set of "candidate" results. Relying on just one retrieval method is a mistake. Modern systems use **Hybrid Retrieval**:
1. **Lexical Retrieval (ElasticSearch/BM25):** Excellent at exact keyword matches, serial numbers, and specific names.
2. **Semantic Retrieval (Vector DB):** The query is passed through an Embedding Model. The resulting vector is queried against a Vector Database (like Milvus or Pinecone) using Approximate Nearest Neighbors (ANN) to find conceptually similar documents, even if they don't share any exact keywords.

Both databases retrieve their top 500 candidates.

## The Re-Ranking Stage

You now have 1,000 documents. But retrieval systems (especially Vector DBs) are optimized for *speed*, not *precision*. 

To organize the final top 10 results shown to the user, the 1,000 candidates are passed to a heavy **Re-Ranker**:
- **Cross-Encoders:** A deep Transformer model that takes the `(Query, Document)` pair and computes a highly accurate relevance score. Because it is computationally heavy, it can only be run on a small subset of documents (which is why we do retrieval first).
- **Learning-to-Rank (LTR):** Often implemented as an XGBoost tree model. It takes the Cross-Encoder score, the BM25 score, and business metrics (like the product's profit margin, popularity, and user click-through rate) to generate the final sort order.

## Latency Budgets

Search is highly latency-sensitive. Amazon famously found that 100ms of latency costs them 1% in sales. A standard AI search pipeline has a strict latency budget of ~200ms:
- Query Understanding: 20ms
- Lexical + Vector Retrieval (run in parallel): 50ms
- Cross-Encoder Re-ranking: 80ms
- Network / Assembly: 50ms
