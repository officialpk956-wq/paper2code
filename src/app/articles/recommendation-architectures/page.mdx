# Recommendation Architectures

<Callout type="tip" title="Key Insight">
Recommendation systems power the modern internet. Unlike computer vision or NLP, recommendation systems deal primarily with incredibly sparse, highly categorical tabular data. The challenge is balancing memorization (knowing that a specific user bought a specific item) with generalization (understanding broad trends).
</Callout>

## The Two-Tower Model

The most common architecture for retrieving candidate items out of a massive catalog (like YouTube's billion-video database) is the **Two-Tower Model**.

- **Tower 1 (User Query):** A deep neural network (or BERT encoder) that takes all information about the user (age, watch history, search query) and compresses it into a dense embedding vector.
- **Tower 2 (Item):** A separate network that takes all information about an item (video title, thumbnail, category) and compresses it into an embedding vector of the exact same size.

The similarity between a user and an item is calculated as a simple dot product between these two vectors. Because the item embeddings can be pre-computed and stored in a vector database, this model can retrieve the top 100 relevant items out of a billion in just milliseconds.

## Wide & Deep Learning

Once you have a list of 100 candidates, you need to rank them precisely. Google's **Wide & Deep** architecture revolutionized this ranking phase.

<SVGDiagram src="/diagrams/recommendation-architectures.svg" caption="The Wide & Deep Ranking Architecture." />

It combines two models into one:
- **The Wide Part (Memorization):** A simple linear model that looks at cross-product transformations (e.g., `User_Installed_App=Netflix AND User_Impression=Hulu`). It is fantastic at memorizing specific, high-frequency rules.
- **The Deep Part (Generalization):** A feed-forward neural network that learns dense embeddings for sparse features. It can generalize to recommend items the user has never seen before, based on conceptual similarity.

By training both parts jointly and summing their final outputs into a sigmoid function, the model achieves the perfect balance of relevance and discovery.

## DLRM (Deep Learning Recommendation Model)

Facebook (Meta) introduced **DLRM** to specifically handle the unique hardware challenges of social media recommendations. 

In social networks, categorical features (like User IDs or Page IDs) are massive, requiring gigabytes of memory just to store the Embedding Tables. DLRM separates the architecture specifically for hardware efficiency:
- Dense features (like age or time-on-site) are processed by a Bottom MLP on standard GPUs.
- Sparse features (like IDs) are processed through massive Embedding Tables distributed across vast pools of CPU RAM.
- The outputs of both are combined using explicit feature interactions (dot products) before passing through a Top MLP.

## Session-Based Recommendations

Traditional models assume static user profiles. But if a user is shopping for a birthday present, their behavior right now is vastly different from their historical average. 

**Session-based architectures** like GRU4Rec (using RNNs) or SASRec (using Transformers) treat the user's current clickstream as a sequence of tokens, predicting the very next click in real-time.
